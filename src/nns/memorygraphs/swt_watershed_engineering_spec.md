# 技术文档：SWT + E(p) + Watershed 纹理分割规范

**适用范围**：视觉扫视系统中的纹理通道、边缘连续性判定、区域分割与后续图结构学习。  
**目标**：
1. 将 SWT 计算独立为单独模块，统一处理输入图像并输出多尺度小波特征图；
2. 在当前文件中，通过 SWT 输出构造边界能量图 `E(p)`，并采用 Watershed 完成无监督纹理分割；
3. 输出按尺度组织的纹理连续性标签图，供 `_compute_texture_resp()` 和后续 episode / attention 逻辑使用。

---

## 1. 总体设计

系统由两个部分组成：

### 文件 1：SWT 计算模块
独立文件中新增一个类，负责：
- 接收输入张量 `[B, C, H, W]`；
- 统一转换为灰度图；
- 进行 SWT（Stationary Wavelet Transform）；
- 输出 `[B, 3J+1, H, W]` 的多尺度特征图。

### 当前文件：纹理连续性与 Watershed 分割模块
当前文件中的 `_compute_texture_resp()` 负责：
- 接收 SWT 输出；
- 通过多尺度能量图 `E(p)` 构建边界强度图；
- 按 `NScale` 组织多组 `alpha(j,b)`；
- 对每个尺度执行 Watershed 或等价的无监督区域划分；
- 返回 `[B, NScale, H, W]` 的 `tensor.int` 标签图。

---

## 2. 文件 1：SWT 独立类规范

### 2.1 类职责
类职责是“图像 → 灰度化 → SWT 分解 → 多通道输出”。该类不得承担分割、兴趣图、episode 逻辑，也不得依赖当前文件的状态。

### 2.2 输入输出

#### 输入
- 张量类型：`torch.Tensor`
- 形状：`[B, C, H, W]`
- 允许 `C=1` 或 `C>=3`

#### 输出
- 张量类型：`torch.Tensor`
- 形状：`[B, 3J+1, H, W]`
- `J` 由 config 配置开放

### 2.3 灰度化规则
若输入为多通道图像，先转换为单通道灰度图：

\[
I_{gray}=\sum_{c=1}^{C} \omega_c I_c
\]

建议默认采用标准 luminance 权重：

\[
\omega_R=0.299,\quad \omega_G=0.587,\quad \omega_B=0.114
\]

若输入本身为单通道，则直接使用。

### 2.4 SWT 输出定义
对灰度图执行 SWT 后，输出每个尺度的近似项与细节项。对第 `j` 层尺度，通常有：
- `A_j`：近似项（approximation）
- `D_j^H`：水平细节
- `D_j^V`：垂直细节
- `D_j^D`：对角细节

输出组织方式定义为：

\[
X = [A_J, D_1^H, D_1^V, D_1^D, \dots, D_J^H, D_J^V, D_J^D]
\]

从而通道数为 `3J+1`。

### 2.5 设计准则
- **不下采样**：SWT 输出必须保持 `H, W` 不变；
- **通道顺序固定**：以便下游统一读取；
- **数值稳定**：输出建议为 `float32` 或 `float16`；
- **批处理支持**：必须支持 batch 维度 `B`；
- **无状态**：该类不维护 episode 状态。

### 2.6 配置项
建议配置项至少包括：
- `J`：SWT 分解层数；
- `wavelet_name`：小波基名称；
- `gray_weights`：灰度化权重；
- `dtype`：输出数据类型；
- `device`：CPU / GPU。

### 2.7 代码准则
- 输入必须先检查维度合法性；
- 输出必须保持与输入相同的空间尺寸；
- 结果通道顺序必须与文档一致；
- 不应在此类中执行 Watershed 或聚类；
- 不应在此类中做兴趣图、边界图、访问痕迹等动态状态更新。

## 3. 当前文件：`_compute_texture_resp()` 规范

### 3.1 职责
该方法负责把 SWT 输出转换为纹理连续性标签图，并以无监督方式完成分割。它只处理纹理，不处理全局兴趣图，也不决定 episode 的下一注视点。

### 3.2 输入
- 输入张量：SWT 模块输出
- 形状：`[B, 3J+1, H, W]`
- 类型：`torch.Tensor`

### 3.3 输出
- 输出张量：`torch.Tensor`
- 形状：`[B, NScale, H, W]`
- 类型：`torch.int`（或等价整数类型）

### 3.4 输出语义
对每个 batch 中的每个尺度通道，返回一个**区域标签图**：
- 同一连续区域内像素的值相同；
- 不相连区域的值不同；
- 标签值表示区域编号，而非概率值；
- `NScale` 个通道分别对应从小到大尺度上的纹理连续性结果。

---

## 4. `E(p)` 的定义

### 4.1 能量图目的
`E(p)` 用于表示当前位置的边界强度或纹理突变强度。它是 Watershed 的基础地形图。

### 4.2 定义方式
对每个像素 `p`，由 SWT 细节系数组合边界能量：

\[
E(p)=\sum_{j=1}^{J}\sum_{b\in\{H,V,D\}} \alpha(j,b)\cdot |D_j^b(p)|
\]

其中：
- `j` 为尺度索引；
- `b` 为方向子带；
- `alpha(j,b)` 为权重；
- `|D_j^b(p)|` 表示该尺度该方向的绝对细节响应。

### 4.3 作用
- `E(p)` 大：更可能处于边缘、纹理突变位置；
- `E(p)` 小：更可能处于纹理内部连续区域。

---

## 5. `alpha(j,b)` 的生成规则

### 5.1 设计目标

`alpha(j, b)` 用于把 SWT 的多尺度细节系数汇总成不同输出尺度的边界能量图。该权重设计需要满足：

* 不同输出尺度对应不同的权重分布；
* 小尺度更关注高频、细节分量，大尺度更关注低频、粗结构分量；
* 权重曲线平滑变化，避免相邻尺度间突变；
* 计算开销低，不依赖监督学习。

### 5.2 记号约定

设 SWT 分解层数为 `J`，输出尺度数为 `NScale`，其中 `NScale <= J`。对每个输出尺度 `s ∈ {1, ..., NScale}`，定义一组尺度权重：

[
w^{(s)}_j,\quad j=1,2,\dots,J
]

用于决定第 `s` 个输出通道对第 `j` 层 SWT 细节系数的关注程度。

再定义方向子带权重：

[
\beta_b,\quad b\in{H,V,D}
]

其中 `H/V/D` 分别表示水平、垂直、对角细节子带。

最终：

[
\alpha_s(j,b)=w^{(s)}_j\cdot \beta_b
]

### 5.3 平滑尺度权重曲线的推荐形式

为了满足“小尺度重细节、大尺度重粗结构”的要求，推荐使用**高斯窗**或**软三角窗**来生成每个输出尺度的权重。这样可以避免硬切分带来的不连续，同时计算代价很低。

#### 方案 A：高斯窗（推荐）

为每个输出尺度 `s` 定义一个中心位置 `\mu_s`，再用固定宽度 `\sigma` 构造平滑权重：

[
\tilde{w}^{(s)}_j=\exp\left(-\frac{(j-\mu_s)^2}{2\sigma^2}\right)
]

再归一化：

[
w^{(s)}_j=\frac{\tilde{w}^{(s)}*j}{\sum*{k=1}^{J}\tilde{w}^{(s)}_k}
]

其中：

* `\mu_s` 从小到大均匀分布在 `[1, J]` 上；
* `\sigma` 取较小的固定值即可保持尺度分离，同时曲线平滑。

效果上：

* 当 `s` 较小（对应小尺度输出）时，`\mu_s` 靠近 1，因此 `w^{(s)}_j` 会更偏向小 `j`，即更重视细节分量；
* 当 `s` 较大（对应大尺度输出）时，`\mu_s` 靠近 `J`，因此更重视低频、粗结构。

#### 方案 B：软三角窗（更省计算）

若希望比高斯窗更轻量，可使用三角窗：

[
\tilde{w}^{(s)}_j=\max\left(0, 1-\frac{|j-\mu_s|}{r}\right)
]

再归一化：

[
w^{(s)}_j=\frac{\tilde{w}^{(s)}*j}{\sum*{k=1}^{J}\tilde{w}^{(s)}_k}
]

其中 `r` 是窗口半宽。该方案只涉及减法、绝对值和 max，计算量更低。

### 5.4 `\mu_s` 的均匀生成方式

为保证 `NScale` 个输出通道从小到大平滑覆盖整个尺度区间，建议让 `\mu_s` 在 `[1, J]` 上均匀采样：

[
\mu_s = 1 + (s-1)\cdot \frac{J-1}{\max(NScale-1, 1)}
]

这样：

* `s=1` 对应最小尺度；
* `s=NScale` 对应最大尺度；
* 中间尺度均匀过渡。

### 5.5 子带权重 `\beta_b`

如果不引入额外先验，建议先使用均匀权重：

[
\beta_H=\beta_V=\beta_D=\frac{1}{3}
]

若希望更强调边缘方向，可略微提高 `H/V` 权重，但建议保持简单和对称，以免引入额外偏差。

### 5.6 小尺度与大尺度的方向偏好

在实现上，`\alpha_s(j,b)` 仅依赖 `j` 和 `b` 的分离形式即可满足多数需求；但若希望更强的尺度分层效果，可让不同输出尺度使用不同的中心 `\mu_s`：

* 小尺度输出：`\mu_s` 靠近 `1`，更关注高频和局部纹理边界；
* 中尺度输出：`\mu_s` 位于中间区域，平衡细节与结构；
* 大尺度输出：`\mu_s` 靠近 `J`，更关注粗纹理和大结构过渡。

这与示例一致，例如小尺度可形成类似：

[
[0.2, 0.3, 0.3, 0.2, 0, 0, \dots]
]

这种在前几个尺度上有较高权重、后续尺度逐渐减小的分布。

### 5.7 计算建议

为了避免重复计算，建议在初始化或图像输入后一次性生成所有 `s=1..NScale` 的权重表：

[
\alpha_s(j,b)
]

然后在 `_compute_texture_resp()` 中直接查表使用，而不是每次动态重算。

### 5.8 推荐默认参数

* `NScale`: 3~6（根据任务复杂度调整）
* `J`: 视 SWT 层数而定，建议 `J >= NScale`
* `\sigma`（高斯窗）: `0.8 ~ 1.5`
* `r`（三角窗半宽）: `1 ~ 2`
* `\beta_b`: 默认均匀

### 5.9 生成规则总结

最终推荐的生成规则为：

1. 先根据 `NScale` 均匀生成每个输出尺度的中心 `\mu_s`；
2. 使用高斯窗或软三角窗构造平滑的 `w^{(s)}_j`；
3. 将 `w^{(s)}_j` 与子带权重 `\beta_b` 相乘得到 `\alpha_s(j,b)`；
4. 用 `\alpha_s(j,b)` 汇总 SWT 各层细节系数，得到第 `s` 个尺度的 `E_s(p)`。

## 6. Watershed 分割流程

### 6.1 输入地形图
对每个输出尺度通道，先构造对应的边界能量图：

\[
E_s(p)=\sum_{j\in G_s}\sum_b \alpha(j,b)|D_j^b(p)|
\]

其中 `G_s` 表示第 `s` 个输出尺度通道包含的 SWT 层集合。

### 6.2 预处理
在执行 Watershed 前，对 `E_s(p)` 做轻量平滑，减少噪声导致的伪边界：

\[
\tilde{E}_s = G_\sigma * E_s
\]

其中 `G_σ` 为高斯核。

### 6.3 种子点 / 标记生成
Watershed 需要标记（markers）。本方案建议使用无监督标记生成：
- 在 `\tilde{E}_s` 上寻找局部极小值作为区域种子；
- 对极小值进行最小距离抑制，避免过密；
- 将这些种子作为初始标签。

### 6.4 分水岭生长
把 `\tilde{E}_s` 看作地形高度图：
- 低能量区先被“灌水”填充；
- 高能量区形成分界；
- 当不同种子的生长相遇时，形成区域边界。

### 6.5 输出标签图
Watershed 结果为整数标签图：
- 同一连通区域内部标签一致；
- 不同区域标签不同；
- 标签值是区域编号，非概率。

---

## 7. `NScale` 的解释与使用

### 7.1 定义
`NScale` 是输出的纹理连续性尺度数，用于将 SWT 的多层信息归并为若干尺度层级。

### 7.2 设计要求
- `NScale` 与分割结果一一对应；
- 每个尺度输出一个标签图通道；
- 从小到大尺度依次对应更粗的纹理结构；
- 小尺度强调局部细节，大尺度强调大块连续区域。

### 7.3 推荐映射
若 `J > NScale`，建议将相邻 SWT 尺度合并后再做 Watershed；
若 `J == NScale`，则每个尺度单独处理；
若 `J < NScale`，不建议使用，应调整配置。

---

## 8. 标签图的数值约束

### 8.1 类型约束
输出必须为整数张量，建议使用：
- `torch.int32` 或 `torch.int64`

### 8.2 区域编号规则
- 每个连通区域分配唯一编号；
- 同一张图不同尺度通道之间标签编号可独立；
- 标签 0 是否作为背景保留，需在实现中统一规定。

### 8.3 连通性定义
建议采用 4 连通或 8 连通的一致标准：
- 4 连通更保守；
- 8 连通更适合自然纹理连续性。

建议默认使用 8 连通。

---

## 9. 与后续模块的接口关系

### 9.1 与 `_compute_texture_resp()` 的关系
`_compute_texture_resp()` 只负责纹理连续性标签图，不负责全局兴趣图，不负责注视点选择。

### 9.2 与 AttentionPolicy 的关系
AttentionPolicy 可以直接读取 `_compute_texture_resp()` 的输出，用于判断：
- 当前局部是否仍属同一纹理区域；
- 是否该沿区域继续扫视；
- 是否该切换到边缘追踪模式。

### 9.3 与 graph1 / graph2 的关系
- graph1 可利用标签图形成局部 proto；
- graph2 可在 episode 结束后利用多个局部标签图进行合并。

## 10. 代码准则

### 10.1 SWT 文件准则
- 仅负责转换与分解，不负责分割；
- 必须支持 batch；
- 必须保持空间尺寸；
- 输入输出 dtype 必须明确；
- 尽量避免在该文件中写任何与 episode 相关的逻辑。

### 10.2 `_compute_texture_resp()` 准则
- 仅依赖 SWT 输出与固定规则；
- 不得引入监督学习；
- 不得依赖外部标签数据；
- 不得把全局兴趣图逻辑混入其中；
- 必须输出整数标签图，并保证同区域同标签。

### 10.3 参数管理准则
- `J` 由 config 管理；
- `NScale` 由当前文件的纹理模块管理；
- `alpha(j,b)` 必须可追踪、可复现、可调试。

---

## 11. 推荐实现顺序

1. 先完成独立 SWT 文件，确保输出 `[B, 3J+1, H, W]` 正确；
2. 再在当前文件中实现 `E(p)` 构造；
3. 再实现 `NScale` 尺度映射与 `alpha(j,b)` 权重；
4. 最后接入 Watershed 标签生成与输出格式约束。

---

## 12. 验收标准

### 12.1 SWT 模块
- 输入 `[B, C, H, W]`，输出 `[B, 3J+1, H, W]`；
- 输出空间尺寸不变；
- batch 维度正确；
- 通道顺序固定。

### 12.2 Watershed 模块
- 输出 `[B, NScale, H, W]`；
- 输出类型为整数；
- 同一连续区域内部标签一致；
- 非连通区域标签不同；
- 不依赖监督标签。

### 12.3 纹理分割效果
- 对明显纹理块能形成稳定区域；
- 对边界处能产生连续的切分；
- 多尺度输出能从小到大反映纹理结构层次。
