# 一、vibecoding行为规范

## 1.1 项目背景

### 项目初衷与思想

**希望构建一个类脑大模型**，模拟人类对世界的观察与思考方式。

### 算法框架

当前的算法框架由编码器+解码器（执行器）构成。
多模态编码器的输入是图片/文字/声音，经过神经网络+图结构处理，输出为多模态图，其中图的节点代表人类认知中的视觉/听觉中的概念/特征/事物等；图中的边代表这些概念/特征/事物的语义连接关系
解码器（尚未构建）接受编码器的输入，并输出动作。

### 当前阶段进度

接受CNN的结果作为编码器的输入，当前的视觉部分是双塔结构，分为Gmem与Gpos。其中Gmem负责存储特征向量以及特征之间的联系，Gpos负责检索激活特征的位置。除此之外还有用于决策眼跳位置的控制器和用于优化眼跳路径的优化器。

## 1.2 文件

所有文档放在了 docs/ 文件夹中

docs/algorithm/ 内是本项目的核心算法，其中Alg_beta.md文档是算法的先行待验证版本，实现代码时主要需要参考该文档；Algorithm_gmp.md文档是算法的稳定版本，只有经过实践和调试完成后才会将算法的先行版写入该文档
docs/forGpt/gpt.md 是写给chatgpt的行为规范，gpt需要严格按照此文档规范行为，包括：设计算法、撰写文档、更改和重构代码、与用户交互逻辑

本项目采用多智能体合作方式，分为：代码小组，算法小组，调试小组
代码小组仅具有更改代码文件的权限，严谨修改算法文档，若有质疑需在对话框中提出
算法小组需要与用户敲定算法细节，并撰写算法文档。
调试小组负责报告代码中可能出现的问题，仅在获得允许时可以更改代码文件。

## 1.3 算法设计原则

核心原则是设计能够模仿人类探索世界和思考方式的通用人工智能模型。
用户的哲学思想是大道至简，即道家思想中的“道生一，一生二，二生三，三生万物”，万事万物遵循整体相同的底层规律，即使用基本的道理和逻辑能够构筑复杂而合理的世界。该道理推广到本项目中，则是希望chatgpt在设计算法是能够：**为复杂的规律或机制找到相似的底层算法**，通过细节的调整或某个维度的**推广**，为所有希望实现的功能找到优雅而普适的算法。如本项目中已经确定采用的设计：图结构特征表征，即是通过节点与边的简单逻辑表征复杂世界；或是其它优雅算法：如transformer，通过自注意力这一核心设计涌现人工智能。
追求优雅和普适可以向复杂度作轻微让步，允许做出不影响整体架构的细微调整以实现算法加速。

总之，**算法设计**需要满足并平衡：
1.优雅性（追寻具有简约的底层设计）
2.模拟人类行为（最好是使用一套设计涌现复杂行为，而非机械地追求形似）
3.普适性（可以推广为多模态，或时域->频域）
4.复杂度

## 1.4 文档撰写

### 何时撰写

任何时刻对代码进行更改或重构时，都需要在docs/record/ 文件夹中撰写文档，记录：本次更改内容的简要概括。同时在docs/record/index.md 文档中添加本次撰写文档的索引，记录其（1）文件名（2）更改的简短概括（3）提交者（chatgpt）和提交时间

在对算法进行探讨时，将商讨内容写入docs/algorithm/Alg_beta.md文档。

### 文档文字风格

撰写文档时尽量追求学术性强，对敲定的算法命名时尽量体现其作用并避免花哨。将复杂算法的文字描述尽量增加数学语言，如有公式要求严谨。

---

## 1.5 更改和重构代码规范

当敲定算法完成后，gpt需严格按照docs/algorithm/Alg_beta.md文档对代码进行更改或重构。

### 超参数

代码中具有明确物理意义且对模型性能有显著影响的超参数应当单独列在Config类中

### 代码鲁棒性和可复用性

代码对输入的处理需要具备鲁棒性，当前设计下的多模态特征输入：缺少一些子模态、某个模态特征输入通道数缺失或增多，模型需要灵活处理

具有明确物理意义、或代表某些明确功能、或有明确生物学指向的片段必须将其封装为独立模块

对已有代码进行修改时注意其可能对前后文造成的影响

### 代码检查

gpt只需关心编译是否通过。调参及其他测试由用户进行。
