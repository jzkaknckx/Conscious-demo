# 基于目标框与类别标签的层级图学习及判别闭环

日期：2026-09-18。状态：算法设计与实现方案，尚未实现。本方案面向当前固定 CNN → GmemI/II/III、GposI/II/III、OnceOptimizer 架构；保留多层图和相对位置关系，增加监督观察入口、实体来源与类别关联、判别读出及评估协议。

## 0. 结论与任务边界

**标签和目标框可以显著减少实体生成中的无约束组合搜索，并让一个有标签的目标在第一次有效观察后成为可检索的 GmemIII 模板。** 但目标框不是像素级前景标注；“类别已确认”“模板受保护”“几何已跨观察稳定”需要分别记录，不能把框内全部特征永久当作目标，也不能把一个样本伪造为三次支持。

推荐先完成两种有明确边界的任务：

- **A：已知目标框的分类。** 训练及测试均获得框，测试不提供类别。它验证图对目标裁剪的判别性，不声称自动发现目标。
- **B：无框输入的目标检测。** 测试仅给整图，需要额外的候选框/多尺度搜索、框定位与检测评价。它才验证自动定位并识别目标。

整图多标签分类可建立在 B 的候选响应上，但不能在测试时偷偷使用真值框。视频和光流适合后续改善目标支持估计与跨帧证据，不能替代这两个任务的标签、读出和评价模块。

## 1. 当前实现与数据条件

现有 `GraphConsolidationOptimizer.learn` 用接触/邻近关系生成有限大小的实体提案，再经 `_align_entity` 和 `_update_entity` 巩固。`_align_entity` 主要要求成员 GmemII semantic ID 相同并满足平移布局，因此外观变化导致区域 ID 改变时，实体容易失配。默认 `graph_max_members=6` 的局部提案也不能保证覆盖完整目标。标签学习应提供直接的目标级提案入口，而不是只降低现有稳定阈值。

现有 `_new_entity` 会为一次观察登记一次 episode 证据；`EvidenceStats.observe` 按 episode 取最大支持，避免相关重放重复累积。`entity_view` 将实体成员展开进行精验，当前主要处理平移。`query_hierarchy` 已有实体 ID、分数、覆盖率、几何误差和位置，可作为读出的基础，但没有监督类别映射和完整分类训练器。

| XML / 对应图片目录样本 | 659 |
| 带 object 条目的图片 | 530 |
| 无 object 条目的图片 | 129 |

全部 object 有 bndbox；本地检查未发现负坐标、越界或退化框。最小起始坐标为 1、没有 0 起点，这与 1-based 标注相容，但不能单靠最小值证明端点约定。解析器要显式记录坐标约定并用原图叠框验证。所有 object 都缺少 difficult/truncated/occluded 字段，不能把缺字段自动当成已确认的无遮挡。

当前 Notebook 示例 `ILSVRC2014_train_00060030.xml` 无 object 条目，不能直接作为“带标签目标”的演示样本。无条目图片也不能在未确认标注完整性时当成所有目标类别的可靠负样本。

## 2. 标注与观察的数据合同

新增 `ObjectAnnotation`：

```text
image_id, annotation_id, object_id, class_id
bbox_original = (x0, y0, x1, y1)  # 内部统一 0-based、右下开区间
coordinate_convention, annotation_source, annotation_version
label_confidence, optional_instance_mask
optional_flags = {difficult, truncated, occluded}  # 缺失为 unknown
```

若适配器声明输入为 1-based inclusive，则转换为 `(xmin-1, ymin-1, xmax, ymax)`。转换前检查图像尺寸，转换后检查 `0 <= x0 < x1 <= W`、`0 <= y0 < y1 <= H`。不要在未配置约定时根据每个框的数值自动猜测。目标 ID 由原图 ID 与原始标注条目 ID 构成；调整裁剪或图像增强不改变其身份。

新增 `SupervisedObservation`：

```text
annotation, view_tensor, image_valid_mask, object_roi_mask
optional_foreground_probability, ambiguous_ownership_mask
transform_original_to_view, transform_view_to_original
episode_id, augmentation_id, source_digest
```

建议 `episode_id=(dataset_version, image_id, object_id)`；同一目标的裁剪/颜色增强/重放共享 episode。图像相同但目标框不同应有不同 object_id。类别监督训练可以反复使用样本做 SGD，但不能因此增加图的独立观察支持次数。

读取失败、坐标不合法、未知标签映射、目标太小以至于没有有效支持时分别记录状态，不静默跳过后仍将样本计为成功学习。

## 3. 图像规范化、坐标与前景范围

### 3.1 首轮采用固定目标视图，而不是修改全部 Gpos 为尺度不变

从目标框向外保留可配置上下文边带，裁取原始像素，等比例缩放并 letterbox 到固定画布。保留原图与视图之间的完整变换 T。示例默认画布 256×256、边带为框边长的 10%，是实现起点，不是已优化的最佳值。

CNN 在含上下文的像素上编码，随后才用目标 ROI 限制建图；不要先把框外像素清零再求导，否则框边会被制造成强边缘。真实图像有效 mask 与目标 ROI mask 必须分开：前者排除 padding，后者限制目标归属。上下文可用于卷积计算，但默认不作为目标成员写入。

T 包含裁剪原点、统一缩放比例及 padding 偏移；Gmem 几何仍用固定视图像素坐标。推理分类采用同样的候选框规范化流程，近似消除目标整体尺度差异，Gpos 内部继续平移检索。它不消除姿态、非刚性形变或尺度引起的特征变化。全图检测要枚举/预测候选框后使用相同流程，不能直接把规范化模板放到任意尺度整图上声称已支持缩放。

所有预处理参数、特征合同、数值归一化范围和角度单位入版本。方向使用已有二倍角插值/置信度接口；不直接对角度做普通线性插值。裁剪边界附近需要标记可评估性，不能把 padding 或被裁掉的结构当作负证据。

### 3.2 目标框提供归属约束，不提供完美前景

最低可运行版本使用框内 mask 建立目标候选组合，同时将成员归属视为弱监督。若区域跨越 ROI 边界，先在当前观察中裁剪该区域的有效支持、重算所需采样/锚点；aps/ori 继续继承裁剪后的 grad 分区及其父 ID，不能独立重分割破坏绑定。

完整观察范围与目标范围的边界应分别记录；裁剪到框外的成员不能据此产生缺失惩罚。多个框重叠时，允许同一低层特征进入不同目标候选，但标记归属不确定，不能直接断言它是某个目标的核心部分。

可选前景细化使用框初始化的分割结果作为软支持概率，不作为真值。GrabCut 的原始研究提供了框初始化前景提取的参考，但并不保证任何框都能得到正确目标掩码。[GrabCut 原文](https://www.microsoft.com/en-us/research/wp-content/uploads/2004/08/siggraph04-grabcut.pdf)

设某区域 r 的有限有效像素集合为 P_r，框内比例为

\[
 o_r=|P_r\cap B|/|P_r|.
\]

有软前景概率时，令 `f_r=mean_{p in P_r∩B} p_fg(p)`；没有时 f_r 只取中性的候选值，并标记来源为 bbox-only，不能解释为像素前景置信度 1。可组合质量 `u_r = o_r * f_r * reliability_r * ownership_r` 排序；这些权重是候选选择依据，与独立出现证据分开存储。

不建议仅靠“靠近框中心”判前景，也不把框内最大颜色区域必选为核心。复杂目标可偏心、细长或有多个部分。

## 4. 带标签 GmemIII 的创建与状态

### 4.1 一个标注实例对应一个候选外观/布局，不是一个类别只有一个实体

同类不同姿态、颜色和形状可以保留多个 GmemIII 模板。类别到模板是“一对多”；GmemII 继续允许被多个实体共享。框内全部区域直接无选择地并入一个超级实体，会混入背景并导致精验成本增长，不作为默认策略。

新增监督元数据可放在 side table 中，保持现有 component_edges 与关系边结构：

```text
EntitySupervision[entity_id]:
  label_id, annotation_ids, source_object_ids
  origin = annotation / self_discovered / video
  confirmation = annotation_confirmed / visually_confirmed / unconfirmed
  protected, independent_support, canonical_box_relative_to_root
  family_ids, member_foreground_priors, rejected/unknown_member_reasons
```

类别标签不写进 CNN 输入向量或 Gpos 相似度通道，避免模型在测试时依赖不存在的真值标签。

### 4.2 “直接稳定”的可执行定义

经校验的标注目标在具有足够有效图成员、几何有效且提交成功后，可立即设置 `status='stable'` 以进入稳定检索池，同时记录 `confirmation='annotation_confirmed'`、`origin='annotation'` 和 `protected=True`。其 `EvidenceStats.support` 仍为 **1 次真实 episode**，不伪造 `support=3`。

因此 stable 的含义扩展为“可持久检索”；是否经过跨观察几何验证由 confirmation/independent_support 单独说明。报告必须分别统计标注确认稳定数与视觉巩固稳定数，不能将前者作为无监督涌现成果。

标注保护仅防止普通候选容量/过期规则无条件删除；不代表永不删除。错误标签撤回、重复模板合并、内存压缩均需显式更新来源与分类读出。一次标注不能无限保护数百个背景碎片，也不能将所有成员变成永久核心。

`_prune_candidates`、`_merge_identical_entities`、`_update_entity`、序列化和查询筛选都要理解这些状态。不能仅改一个 status 字符串而留下其他路径按旧假设处理。

### 4.3 标签不能代替重复样本去重

对相同 `(source_object_id, annotation_version, preprocessing_version)` 重放，首先检查 observation ledger：已完整提交的同一实体观察不重复建新标注种子，统计可增加 raw hit，但独立支持最多一次。若先前预算截断或成员不完整，可以继续补全，保留同一 observation/entity 关联，不新建一份“稳定实体”。

增强视图也不得因不同 tensor digest 被当作独立对象；显式 episode_id 优先。对不同图片的同类实例，允许新增观察，但仍不能只凭类名把其几何平均到同一个模板。

## 5. 框内成员选择、角色与几何

### 5.1 选择单位与预算

将一个 grad 区域及其有效 aps/ori 子区域视为一个“边缘属性组”，选择时优先保持组内关联；RGB、curv 区域作为其他候选组。同组共享来源，不作为三次独立证据。

新增独立的 `supervised_member_budget`，建议起始 24 个 GmemII 成员、最多 8 个主区域组，并以总叶槽位预算限制最坏精验成本。它不等于将所有无监督提案的 `graph_max_members` 一起增大。各数值须通过训练/验证集测试，不能假定 24 个成员已经足够表示所有目标。

一个可实现的确定性选择流程：

1. 排除不可写、ROI 无交集、几何无效的区域；保留原因统计。
2. 按 u_r、空间覆盖增益和信息区分度排序，采用固定破同分规则。
3. 在 4×4 ROI 网格中优先覆盖尚未覆盖的位置，避免只选一个高纹理角落；该网格仅用于候选多样性，不写成几何真值。
4. 同一边缘组逐个加入可用属性，确保剩余成员/叶槽位预算；单个父区域没有有效属性时可只保留 grad。
5. 达到预算即记录截断；未被观察或因预算未选中的角色不记负证据。

至少需要两个有效 GmemII 成员且展开几何一致，才创建当前定义的 GmemIII。只有一个有效区域时返回 `INSUFFICIENT_STRUCTURE`，可继续作为 GmemII 分类样本，不虚构第二个角色来凑实体。

### 5.2 根与相对位置

选择有效、可靠且接近已选成员空间中位位置的区域作为 root，优先选具有稳定支持的 grad；不要求 root 必须对应某个固定类别语义。成员偏移为 `delta_i = anchor_i - anchor_root`，保留当前根到成员的星型边及已有必要几何约束。

同一 GmemII 多次出现时必须使用不同 role ID，不能按 semantic ID 去重而丢失两个眼睛、两只轮子等结构。额外记录框相对 root 的四条边偏移，供检测阶段恢复目标范围。根改变需一次性重锚整个实体和框偏移，而非只移动部分成员。

`entity_view` 的权重需要按边缘属性组分配：先给主组分配总质量权重，再在 grad/aps/ori 成员间分摊。现有按成员组各自归一化会使绑定的三种属性被额外计权；监督实体应显式提供 family_id 和 family_weight，防止仅因为多三个通道视图而压过目标其他部分。

### 5.3 背景成员的修正

首次框内成员均是“受目标框约束的候选成员”，而非不可删除核心。跨独立目标观察中稳定出现、且与目标布局一致的成员可提升为核心；可评估但反复缺失的成员降低权重或移出。全局低层节点可以共享，改变的是实体从属关系。

已有 pending_members / EvidenceStats 可复用，但机会计数只能在该成员按视野、遮挡/软掩码与搜索完整性可评估时增加。人工标签保护实体类别来源，不保护每一个背景成员。只有软前景估计时，不把掩码外像素一律当成确证负例。

## 6. 同类归并与跨观察巩固

### 6.1 直接标注学习流程

```text
校验标注与训练划分
→ 规范化目标视图、编码和有效/ROI 掩码
→ 原子建立或复用 GmemI/GmemII 区域（保留 grad 属性绑定）
→ 选择目标成员组，形成一个目标级提案
→ 对同类已有实体做高召回候选搜索和几何精验
→ 唯一合格匹配：增加该实体的真实观察证据、更新可评估成员
→ 没有合格匹配：建立带标签、受保护的稳定种子
→ 模糊或搜索未完成：保留 observation 待处理，不直接复制新实体
→ 原子提交图、监督元数据、类别关联和观察 ledger
```

训练时类标签可限制实体归并候选，但 **分类特征提取和推理必须搜索所有候选类别**，不能根据真实标签预筛后再报告准确率。GmemII 仍跨类别共享；GmemIII 默认不自动跨不相容标签合并。相同视觉结构同时关联不同类别时保留标签冲突信息或不同类的模板身份，交由读出处理，不能静默覆盖标签。

如果粗筛不完整、预算耗尽或模板无效，返回 `UNRESOLVED`；监督标签保证目标类别，不保证当前检索已经证明它需要一个新的实体模板。

### 6.2 改善“必须相同 GmemII ID”的限制

保留精确 semantic ID 作为最快对应；没有足够精确对应时，在有限成员集合之间建立兼容关系，条件包括模态/属性组兼容、区域外观相似度达到召回阈值、相对位置在允许范围内。标签只用于候选路由，不直接制造成员相似性。

以若干可靠对应生成平移假设 t，在每个假设下构造代价

\[
 C_{ij}=\lambda_a(1-s_{appearance}(i,j))
       +\lambda_p\,\rho(\|x_i-(d_j+t)\|/\sigma_p)
       +\lambda_q(1-q_i),
\]

不兼容对代价为无穷，增加未匹配虚拟项；做一对一最小代价指派，避免一个观察区域满足多个同模态角色。每个假设后复核覆盖率、反向覆盖、实际边残差与竞争间隔。成员数受预算限制，指派可采用小矩阵求解。结果仍需连续叶证据精验，不能用区域摘要替代最终判断。

同类多姿态不能对不相容几何强行取均值；未满足对齐时保留不同模板。多模板共同关联同一类别，由分类读出聚合。在标签版本确认前后，不因分类头预测正确就自动把自预测当真实监督证据。

## 7. 判别读出：无需随节点数无限扩展分类维度

### 7.1 最低可运行的类别证据头

标签已给出实体到类别的关联。对目标视图 x 的 GmemIII 匹配 m，定义

\[
 a_m=\mathbf1[\text{accepted}]\,s_m\,c_m
      \exp(-e_m^2/(2\sigma_g^2)),
\]

其中 s 为匹配分数、c 为 matched_coverage、e 为几何误差。可评估覆盖不足时仍遵守精验拒绝规则。按类别聚合

\[
 h_c(x)=\max_{m:\operatorname{class}(template_m)=c} a_m,
\]

无命中时 h_c=0，但另存搜索是否完整与是否存在可评估候选。使用 max 而非累加，避免同类增加大量重复模板后仅靠数量抬高分数。新增节点不会改变 h 的维度 C，但可能改变最大值分布，新增记忆版本后仍需校准。

**一例学习基线**：直接用 `argmax h_c`，配合验证集确定的最低分数与间隔作拒识。有足够匹配时允许输出类别，同时标记候选搜索是否完整；稀疏近似查询的正预测不宣称是穷举最优。完整搜索仍无合格响应时输出 UNKNOWN，搜索不完整且缺少足够证据时输出 UNRESOLVED，不能因为当前稀疏查询通常不完整就把所有正匹配一律废弃。若使用 `softmax(h/T)`，它只是待校准的类别分数转换，不应称为天然概率。

这一基线无需额外为每个增长节点学习分类列，最适合先检查“有标签稳定模板是否具有判别性”。它只用 GmemIII；必须同时报告无法建立实体的样本和查询无响应率，不能删除这些失败样本提高准确率。

### 7.2 可训练的固定维度分类头

每类保存最佳匹配的 `(h_c, evaluable_coverage, matched_coverage, normalized_geometry_error)` 及缺失/未决标志，按固定类别表拼接，并附加固定维度的 GmemII 读出 g(x)：

\[
 z(x)=[h,\text{per-class quality/masks},g(x)],\quad
 \ell=Wz+b.
\]

g(x) 可由共享的区域内容编码器对模态特征、相对位置和角色做固定维度集合聚合，维度建议先取 128；若暂不实现 g，先训练纯实体证据头，明确它对无实体样本的局限。禁止把 GmemII semantic ID 直接当连续数值输入。

单目标分类采用 softmax/交叉熵，整图多标签采用独立 sigmoid/BCE。类别权重仅由训练集计算；分类优化器与图结构优化器分开。冻结 CNN 和离散图检索时，梯度只更新共享读出/线性头，不宣称已端到端训练图。

为使可选 GmemII 读出可直接实现，可先将每模态有效原型通道（不含 gate-only 置信度）投影到 32 维，将其与相对区域 root 的二维坐标、角色标志拼接，经共享 MLP 得到 32 维叶表示；按槽位权重池化，并拼接已有边偏移的 16 维编码及支持质量统计，再投影为 64 维区域表示。对查询中的区域匹配按匹配质量做加权均值与逐维最大值拼接，得到 128 维 g(x)。重复位置先去重，空集合用零向量加显式 empty 标志。相对坐标使用固定视图尺度归一化，不使用原图类别或真实框尺寸作标签代理。该实现是起始读出，不保证聚合对所有不同图结构都具有唯一性。

监督目标为 `L = sum_i w[y_i] * CE(logits_i, y_i) / sum_i w[y_i]`；多标签时改为逐类 BCE 并屏蔽未知标签项。可从 batch=32、Adam 学习率 1e-3、权重衰减 1e-4、最多 50 个 epoch、验证指标连续 5 个 epoch 无改善即停止开始，保存最佳验证快照；这些参数仅为可执行初值，尚未调优。首轮冻结图与检索、先只训练线性头；加入共享 MLP 后再训练 MLP 和头。分类增强共享原图划分，缓存的冻结图查询特征不得跨图版本混用。

若目标类别集合增长，扩展的是类别输出 C，而不是每个图节点；类别新增会改变 softmax 归一化，需旧类回放和重新校准。每类模板数量可以增长或合并，映射与模板版本必须随检查点保存。

### 7.3 避免自匹配制造虚高训练表现

同一张训练裁剪刚建立的模板必然容易匹配自己，不能据此证明泛化。推荐在训练集合内部再划分 `memory_build` 和 `readout_fit`：前者建图，后者只查询、训练分类头，不写图；验证/测试均不写图。类别证据头的一例学习基线不需要 readout_fit，可直接用独立测试评估。

如果宣称 k-shot，目标类别上所有用于建图、拟合分类头或调阈值的带标签样本都计入监督预算。不能每类用一张图建模板、再用几十张同类标签训练头，仍称整个系统为 one-shot。固定读出或在不相交基础类别上预训练共享头，才适合严格少样本协议。

后续持续学习可阶段性冻结图、用训练回放重新计算读出，再更新头。改变模板或索引后，缓存键至少包括图版本、特征合同、预处理和读出参数版本。

## 8. 无框输入：检测与整图判别的额外算法

已知框分类完成后，B 任务还需要以下模块，不能省略：

1. **候选 ROI**：用滑窗/图像金字塔加多种宽高比建立可复现基线，或接入独立候选生成器。候选召回率先在训练/验证标注上测量；若使用外部预训练模型，单独声明其监督来源和贡献。
2. **规范化编码与检索**：每个候选调用与训练相同的 ROI 变换；可批量 CNN 编码。候选预算截断需记录，不将未检索位置标成没有目标。
3. **框恢复**：利用实体 root 匹配位置与存储的 `canonical_box_relative_to_root` 得到候选视图中的目标框，再经 T 的逆变换回原图。记录置信度和可见成员覆盖；root 坐标本身不是检测框。
4. **框细化**：可先以候选框作 baseline；进一步训练四维框偏移回归，用标准化中心偏移和对数宽高比目标，损失为坐标回归损失，仅在与真值 IoU 匹配的正候选上训练。
5. **去重与多实例**：按类别和 IoU 做 NMS/软抑制，同类相邻目标不能只按 root 距离合并；一个模板可以产生多个实例。
6. **无框评价**：测试时移除真值框输入，预测仅用于最终 IoU 匹配与 AP 计算。报告 proposal recall、分类错误、定位错误和未决率，区别各模块的失败。

整图多标签分类可对候选的每类分数做 max 池化；多个候选大量重叠时不能直接按独立概率相乘。整图级阴性监督只在类别标注完整时成立。对本地无 object 的 129 张图，先确认其标注完整性再决定是否用作背景训练。

## 9. 前景/背景判别的增强策略

框监督建立的是目标实例关联，不是前景真值。为减少学习背景捷径，建议进行以下独立对照：

- 同一目标的框边抖动、上下文范围变化，观察哪些成员持续出现；增强共享 episode，不增加独立支持。
- 有可靠 mask 时替换背景、保持目标；没有 mask 时仅改变框外上下文，不伪称已替换框内背景。
- 加入“背景相似但目标不同”和“目标相同但背景不同”的真实样本，比较类别响应与成员贡献。
- 有完整标注时选与所有目标框低 IoU 的区域作为背景候选；边界附近及未标注对象可能存在的区域设 ignore，不能任意标负。
- 可引入额外实例分割模块提供软掩码，但需报告它的预训练数据与误差，不将其能力计入本模型独立学习的成果。

若背景成员反复主导类别响应，可使用成员消融贡献与跨样本选择性调整 membership 权重；在保留核心结构的前提下减少不稳定上下文。仅凭“一次框内出现”无法解决前后景歧义。

## 10. 视频与光流路线的可行性及接入方式

当前 `RetinaModel.forward` 中 frame difference 和 flow 调用仍被注释，`flowvelocity` 返回零张量。因此视频学习不是把图片循环改成连续帧就已经具备，需要新增时间状态、真实流估计和跟踪接口。

运动信息可辅助实例分离，但相机运动、视差、遮挡和静止目标使“非零光流=前景”不成立。相关研究将相机/场景运动与物体运动联合建模，而非仅对流幅值阈值分割。[Optical Flow in Mostly Rigid Scenes](https://openaccess.thecvf.com/content_cvpr_2017/html/Wulff_Optical_Flow_in_CVPR_2017_paper.html)

建议后续按以下流程接入，先不把 flow 强行新增为 Gmem 的持久外观模态：

1. 对相邻帧计算双向光流、前后向一致性与遮挡掩码；保留曝光变化及运动模糊质量标志。
2. 估计背景/相机运动，计算残余运动；简单全局仿射/单应模型可作基线，但对视差场景保留未知，不声称完全分离前景。
3. 以外观、残余运动及时间对应建立目标轨迹，处理出生、消失、遮挡和 ID 切换。
4. 将轨迹框/软前景概率送入与框监督相同的 SupervisedObservation；无类别标签的轨迹只能创建视觉实体，不能自动赋语义类别。
5. 相邻帧的同轨迹视图视为相关证据，按 tracklet/时间窗口及外观新信息控制有效支持；不能每帧都加一次独立观察。
6. 标签沿轨迹传播要有置信度和冲突检测；跟踪 ID 切换时停止传播，不能把错误轨迹污染稳定实体。

视频可减少成员背景混入并提供不同视角，但新增系统复杂度明显高于现有 XML 框监督。当前优先完成静态标注闭环，再接入视频的框/掩码/对应关系，是风险和工作量更可控的顺序。

## 11. 模块接口、状态与实现顺序

| 模块 | 最小接口 / 输出 | 必须处理的事项 |

| ObjectRegionSelector | `select(report, observation)` | 绑定属性组、预算、归属不确定、截断原因 |
| SupervisedGraphOptimizer | `learn_object(observation)` | 复用/新建/未决、标注保护、幂等 ledger、原子提交 |
| EntitySupervisionStore | ID→标签/来源/状态 | 合并删除重映射、标注撤回、独立证据 |

| ClassifierTrainer | `fit/readout/predict` | 监督预算、类别不均衡、冻结图、校准、回放 |

| CheckpointManager | `save/load` | 图/标注/类别/预处理/头/索引/随机种子版本一致 |
| ProposalDetector（任务 B） | 无框输入→候选框 | 召回、坐标逆变换、多实例 NMS、IoU/AP |

`learn_object` 建议返回：`MATCHED_UPDATED`、`ANNOTATED_SEED_CREATED`、`ALREADY_OBSERVED`、`INSUFFICIENT_STRUCTURE`、`UNRESOLVED`、`INVALID_ANNOTATION`。分类输出同时包含类别分数、top-k、最佳实体及位置、搜索状态和拒识原因。

第一阶段只实现 AnnotationDataset、ObjectViewTransform、目标选择、监督种子和类别证据读出，即可完成不带额外训练头的已知框分类；第二阶段加入独立 readout_fit 的分类头和同类对应改进；第三阶段完成无框检测；视频最后接入。每阶段都应有冻结快照和失败案例，不要等待所有模块完成才检验设计。

## 12. 配置建议与数值边界

| 配置 | 起始策略 | 说明 |
| --- | --- | --- |
| `supervised_seed_policy` | annotation_confirmed | 首次合法观察可持久检索，证据仍为 1 |
| `supervised_member_budget` | 24 | 与无监督局部提案预算分开 |
| `supervised_family_budget` | 8 | grad/aps/ori 作为关联主组 |
| `supervised_leaf_budget` | 512 作为起点 | 控制展开后的精验规模；不能只有成员数限制 |
| `object_view_size` | 256 | 复用当前 CNN 分辨率 |
| `object_context_fraction` | .1 | 只用于编码上下文，默认不写成成员 |
| `object_min_inside_fraction` | .8 作为起点 | 仅筛选/排序，不能解释成前景概率 |
| 区域/实体精验阈值 | 先沿用当前默认值 | 不因标签已知就无条件接受错误几何 |
| 类别拒识阈值、分类温度、NMS IoU | 验证集校准 | 不使用测试集选择 |
| 预算耗尽 | UNRESOLVED、不部分提交 | 不能当新颖性证据 |

这些是可实施的初始策略，不是已验证最优超参数。掩码缺失、通道缺失、极小 ROI、重叠实例、非有限特征、重复成员、空激活均必须有明确输出，不用异常吞掉整个 batch。

## 13. 实验协议与验收标准

### 13.1 数据划分与少样本定义

先从至少出现在 10 张独立图片中的类别选择首批，按原图分组划分，避免同图不同框及增广跨集合。多类同图会使简单逐类切分冲突，需要统一分配图像并检查每类覆盖；划分不满足最低样本要求时减少类别或扩充数据，不复制样本填满测试。

普通监督实验可在训练集内部拆 memory_build/readout_fit，并另留 validation/test。严格 k-shot 实验则每类仅允许 k 个训练来源参与目标类别监督，使用固定类别证据读出或在其他类别上训练的共享头。额外人工掩码、预训练模型和类别标签均记录其监督来源。

### 13.2 必须通过的功能检查

- XML 坐标往返与原图叠框正确；CNN 编码前后 ROI 对齐，padding 不成为成员。
- 标签种子第一次有效观察即可查询，独立 support 不伪增；重复 episode 不不断产生新稳定节点。
- 不同标签不静默互相覆盖；同类不相容姿态不被强行平均。
- aps/ori 保持 grad 父区域及有效门控；跨模态组不过度重复计权。
- 空/单区域目标返回明确状态，不伪造结构；预算截断不写成“未见过”。
- 冻结查询和测试不会修改图、来源表、类别权重或索引统计中的持久状态。
- 检查点恢复后的类别 ID、图节点、元数据和读出维度一致；删并节点同步处理标签关联。

### 13.3 判别与结构质量指标

任务 A 报告 accuracy、macro-F1、每类召回、混淆矩阵、无实体率、拒识/未决率；闭集主指标必须包含失败样本，另报告已接受样本准确率与覆盖率，不能只报后者。对极少测试样本用按原图重采样的区间或重复分组划分说明不确定性。

任务 B 报告明确 IoU 标准下的 AP/mAP、proposal recall 和分类/定位错误分解。整图多标签报告每类 AP、macro/micro-F1，不与单目标 accuracy 混用。

图方面报告标注种子数、视觉巩固数、每类模板数、同源重复创建率、跨观察复用率、成员稳定率及实际背景敏感性。对框监督下没有像素真值的样本，不报告未经定义的前景 IoU。

消融至少包含：CNN 池化分类、无监督图读出、框监督图、框+软前景图、GmemII-only、GmemIII-only、二者联合；同样数据划分、监督预算及读出训练条件。补充背景交换/上下文变化、布局打乱、遮挡与尺度扰动，验证模型是否依赖组合排布而非背景捷径。

所有阶段记录建图时间、查询时间、分类头时间、峰值 RSS/显存、候选量、预算截断和图大小。框监督预计减少无关提案，目标模板却可能更大，净加速必须实测，不能仅依据框内像素较少推断。

## 14. 最终建议

先让一个标注实例生成一个可解释、可重放、受保护的实体种子，并用固定类别证据读出完成已知框分类。这能直接检验当前层级图是否具有目标判别能力，同时保留成员背景纠错和跨观察巩固的空间。之后再引入可训练分类头、相似区域角色对应与无框定位；视频作为额外的前景和对应证据来源接入，而不是替代监督闭环。
