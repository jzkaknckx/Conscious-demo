## 1. 疑问一：相同编码的多个节点如何处理

### 1.1 共享编码是索引设计的正常结果

粗编码故意压缩信息。两个实体都含“红色、圆形”，可能是相同物体的两个观察，也可能分别是苹果与红球；同样的节点集合还可能形成不同布局。**粗编码不是唯一节点 ID，相同编码不能直接合并节点。**

应将一个编码对应到 posting list，即一组候选 ID，再使用更细的外观、数量、角色与几何约束区分。需要解决的是候选表过大和重复精验，而不是强迫每个节点拥有不同代码。单纯给新节点附加一个唯一位，查询端不知道该位应如何激活，不会提高检索能力。

目前有两套相关索引：全局 `HypergraphIndex` 以精确原型签名建立类别和倒排关系；学习阶段 `BinaryCoarseIndex` 以量化原型区间建立位图和加权上界。后者仍扫描同模态模板，并非通过一个代码直接定位很短的模板列表；前者仍逐类计算特征事件。这是改进接入方式的切入点。

### 1.2 先删除“与相似度无关的编码差异”

当前签名/量化键包括完整原型数值，包含 ori 新增的 gate-only 置信度通道；这些通道不参与原型相似度，却能使两个等价相似度原型分到不同类别。建议为索引单独定义“相似度签名”：由模态、合同版本、参与度量的通道及其 mask/参数构成；gate-only 数值继续保留在图节点中，不参与相似度类别划分。

这不是删除置信度门控。查询门控仍使用输入置信度，只是不让记忆中的非度量数值妨碍等价响应复用。任何这种折叠必须先确认相应门控不依赖原型的被删除值。方向周期可作一致的规范化；梯度向量范数则不能未经验证直接归一化后宣称响应严格等价，因为现有度量包含数值正则项。

随后按“共同位图/共同粗描述”合并索引桶、共享桶级检查，保留桶内全部模板 ID；只对真正通过几何及证据等价检查的模板进行记忆合并。

### 1.3 树状二进制编码可行，宜作为自适应索引树

推荐的树节点存储一个可从输入计算的分裂规则，例如颜色某通道阈值、轮廓尺寸范围、方向类别，或某个局部角色/相对位置是否可能出现。叶子存候选列表：

```text
模态 / 合同
  └─ 粗外观类别
      ├─ 子范围 A
      │   ├─ 局部角色/布局特征 P 可能出现 → 候选列表
      │   └─ P 不可能出现 → 候选列表
      └─ 子范围 B → 候选列表
```

所谓“出现重复就新增标签”，只有在标签表达可检测的差异时才有用。建议在桶过大且新的分裂能明显降低期望精验成本时才分裂；完全相同或当前观测无法区分的对象继续共用叶子。设置最小叶容量、最大深度和合并滞后，防止每来一个样本就改树。

**安全粗筛不能强制只走一个分支。** 输入是带噪声/不确定性的特征范围：与两个子范围都相容时访问两支；未知角色也访问所有可能分支。空间关系判别必须包含现有位移容差及可评估性规则。树的分裂主要改变计算顺序和范围上界组织，不能取消前文“精验可接受 ⇒ 粗筛保留”的要求。

平衡树在可选择性查询下可以接近 `O(log L + K)` 的定位成本，L 是叶数、K 是访问候选量；边界/遮挡/范围过宽时仍可能访问整棵树。不能承诺在保留无漏筛保证的同时，使所有查询都为对数复杂度。

### 1.4 推荐分层表达，不把所有差异压进一条不断增长的位向量

推荐逐层补充信息：

1. **外观层**：共享低层相似度类别，沿用保守区间兼容判据。
2. **角色与计数层**：某类出现一次还是多次、是 anchor 还是 peri，使用稀疏计数或少量分档；未知计数保守处理。
3. **布局层**：存储已有图边的相对方向/距离类别、区域跨度、闭合性或局部曲率分布，挑选有区分度的局部结构。不要枚举所有类别对的笛卡尔积。
4. **精验层**：使用原始连续特征、实际边偏移、覆盖率及冲突校验。

绑定后的 grad/aps/ori 是同一条边的三个属性视图，适合组合成一个局部索引特征，例如“某段边缘的方向与 aps 区间”。这可以提高选择性，但三种响应共享输入证据，不能当作三份独立出现证据加权。

树路径应与稳定图节点 ID 解耦；索引重建不应改节点身份或分类头维度语义。

### 1.5 存储开销是否会失控

有 L 个非空叶子的二叉树，若每个内部节点都有两个子节点，内部节点约 L−1，树元数据可为 `O(L)`；加上 posting 关联总数 P，主要开销为 `O(L+P)`。每个节点若存 d 维包围范围，还需 `O(dL)`。同一模板多桶归属会增加 P，应监控复制倍数。

相反，若每次冲突都在全局位空间新增一位，并为所有 N 个模板保存密集位图，存储约为 `N*M/8` 字节；当位数 M 与 N 同步增长时，会趋于平方级。不要采用这种全局追加独占标签方案。

当前 Python 整数位图还存在“最大位编号”开销：不是只有置 1 的位才占空间。例如 GmemIII 的成员位使用 `1 << semantic_id`，语义 ID 增长或存在删除空洞时，整数长度随最高 ID 增长。索引内部可使用快照级紧凑 class ID，再映射回稳定节点 ID；稀疏 posting/排序 ID 数组适合只有少量成员的模板。不要用长树路径反复拷贝取代稳定 leaf ID。

下一次日志应增加：相同高层位图的桶数、每桶模板数 p50/p95/max、posting 访问量、各模态排除率、索引构建时间、位图字节数、类数量增长率及候选重用率。目前缺少这些指标，不能凭总体排除率判断该采用哪种树深度。

## 2. 疑问二：多核同时计算是否可行

### 2.1 可行，但提高线程数不会自动并行当前流程

当前主要执行链是 Python 区域/模板/槽位循环，夹杂 CPU NumPy 操作、GPU 小算子和设备结果回传。普通 Python 多线程不适合直接加速大量字典/集合操作；一些原生数组算子可释放解释器锁，但是否并行仍取决于具体算子和任务粒度。`torch.set_num_threads` 只控制相关 CPU 算子，不能把 `_region_match` 的外层循环自动分摊到各核。

20 个逻辑 CPU 下，总体约 5% 与一条满负荷工作线程相容。同一线程迁移会出现多个核交替满载。现有日志不是 CPU 调用栈采样，不能量化 GIL、原生计算和 GPU 等待各占多少。

### 2.2 优先处理目前最明确的串行浪费

`_relations_and_proposals` 对每个区域对扫描全部 `gii.region_relations.items()` 查变体，新增关系时又计算字典最大 key。最终 174,169 条关系使这条路径明显放大。

建议先维护 `(source_semantic_id,target_semantic_id) → 关系变体列表` 和单调递增关系 ID；有必要时再对相对位置变体做分桶。这样从每对扫描整张关系表改为只扫描该对的少量变体，且不改变双塔结构。索引必须在模板合并/删除时更新。此项目前比先引入复杂多进程更值得优先实施。

全局先验查询也应增量维护特征类别与模板视图，避免每图重建静态部分、逐个精确原型重复生成事件；这与问题一的共享索引应统一设计。减少浪费后再做并行，才能避免把内存扫描放大到所有核。

### 2.3 并行边界：读同一快照，统一提交

当前 `learn` 已经让所有区域读取同一旧记忆，再深拷贝并写入，是适合利用的边界：

```text
输入编码 / 构图
       ↓
冻结本步记忆版本 + 准备连续数组/索引
       ↓
按区域或模板块并行粗筛、评分/几何验证
       ↓
按原区域与模板次序归并结果、诊断和歧义
       ↓
单个提交者更新节点、关系、证据和索引
```

必须避免工作线程共享修改 `work_counts`、LRU 缓存和预算状态；每个任务返回局部结果和统计，统一归并。排序、相同分数的破同分规则、异常处理及预算到期状态需要确定性。一个任务失败不能让部分区域先提交。

### 2.4 两条实际可选路线

| 路线 | 适用工作 | 关键代价与限制 |
| --- | --- | --- |
| 编译后的 CPU 数组并行 | 上界归约、几何残差、关系候选与纯 CPU 粗筛 | 先把 Python 对象整理成连续数组；控制线程数，避免内存带宽争用 |
| 常驻 CPU 工作进程 + 一个 GPU 计算服务 | Python 密集且难以短期重写的只读候选任务 | 使用共享只读数组，避免每任务 pickle 整图；GPU 任务统一合批，不能让每个进程独占一套模型/缓存 |

多进程建议先用 2/4 个常驻进程做同快照基准，逐步测到 8；不要按 20 个逻辑核直接开 20 份 Python 图。GPU 已初始化后也不宜直接 fork 复制其运行状态；采用明确的进程启动和 GPU 所有权边界。

对于现有 GPU 评分器，更直接的路线是将多个槽位/模板块合成 GPU 批次，减少 CPU 回传上界判断，而不是让多个 CPU 线程同时向单卡发射零碎算子。CPU 并行与 GPU 批处理可以配合，但要分别测量。

并行处理不同图片的学习会改变在线记忆更新顺序，不能视为严格等价加速。可以并行预编码/预取，或者对冻结快照进行多图评估；本步写入仍串行提交。异步学习若以后需要引入，必须定义过期快照的重验证策略。

### 2.5 收益上限与验收

以第 38 步为例，若只有占比 56% 的区域匹配可理想四路并行，其他全部串行，理论加速也只有约 `1/(0.44+0.56/4)=1.72`，实际还要扣除通信和同步开销；这只是说明并行范围重要，不是预测实测速度。关系、查询和复制的占比继续增长时，收益会更低。

比较吞吐、单步 p50/p95、worker RSS、共享内存、CPU 时间、GPU 算子时间及输出一致性；高利用率本身不是验收标准。后续 profiling 应分出索引构建、粗筛、CPU 上界、GPU 响应、回传、完整赋值，而非只记录整个 region_matching。

## 3. 疑问三：如何在增长节点的图上设计分类头

### 3.1 先区分增长的是记忆节点还是类别

图节点表示视觉原型/区域/实体，不等于类别标签。一个类别可以关联多个节点，一个局部结构也可服务多个类别。首先可以固定标注类别集合 C，允许图节点数 N(t) 增长；类别本身也新增是另一项任务。

分类训练样本不是“每个节点一个标签”，而是**带真实类别的图片或目标裁剪经过检索得到的激活集合**。当前 659 张 DET 图片包含多类同图，不能按文件夹标签训练。建议先做真值框裁剪单标签分类，再做整图多标签；按原图来源划分训练/验证/测试，所有建图和类别头更新只用训练部分。

### 3.2 方案 A：可扩展稀疏线性读出，最容易建立基线

为每个稳定节点 ID 维护读出列，图片对模板 j 的位置池化激活为 `a_j(x)`，例如已接受匹配的最大分数。模型为

\[
 \ell_c(x)=b_c+\sum_{j\in A(x)} W_{cj}a_j(x),\qquad W\in\mathbb R^{C\times N(t)}.
\]

A(x) 只含实际激活节点，使用稀疏 gather/累加，不构造每图数万维密集输入。按 GmemII/GmemIII 分别维护列或层级块，附加匹配覆盖、几何误差和未决标志；stable 节点太少时不能只读 stable GmemIII，否则很多图没有有效输入。

新增节点时：分配新的稳定列索引，将对应分类权重初始化为零。**若旧节点激活和预处理不变、类别集合不变**，新列初始化不会改变原 logits。随后用带标签训练样本学习新列，不能由节点出现本身推断类别。若预处理按全图节点数归一化，或新增候选改变了检索预算中的旧匹配，这一不变性就不成立。

工程上建议分块扩容权重，或显式迁移优化器状态。直接替换 Parameter 后，优化器仍可能指向旧对象；需保留旧块权重、动量/二阶矩和训练步信息，只给新块初始化状态。已有状态不能因一次节点新增全部重置。

节点生命周期规则：

- **重编号**：读出使用独立稳定 ID→列映射，不使用本轮粗筛 class ID 或树路径。
- **删除**：先留 tombstone，冻结/屏蔽相应列，周期性压缩并保存映射；不存在的节点输入为零。
- **合并**：只有在所有输入上两个旧激活完全相同且等于新激活时，`W_new=W_a+W_b` 才严格保持 logits。通常并不满足，应重算回放样本并再训练/蒸馏，不能简单平均两列。
- **模板内容更新**：同 ID 的几何或外观变化也会改变特征含义，必须记录版本并用训练回放评估漂移。

存储为 `O(CN)`。例如 10 万节点、125 类、float32 权重约 50 MB；两个 Adam 状态再约 100 MB，训练梯度还约 50 MB。这个数量并非立刻不可承受，但会随节点和类别继续增长。该方案对新节点的类别迁移较弱，适合作为能解释、能验证的第一基线。

### 3.3 方案 B：共享结构编码 + 固定维度集合读出，推荐长期使用

让所有图节点共用一个内容编码器 `phi`，输出固定 d 维向量 `h_j`，而不是为每个 ID 学一个独立 embedding。新节点产生后，直接根据其内容获得表示：

\[
 h_j=\phi(\text{模态、叶原型、角色、相对坐标、图边、版本对应的内容}).
\]

一种与现有层级兼容的实现：GmemI 各模态向量经各自的小投影得到统一维度；GmemII 对成员 `(低层表示, 相对 anchor 坐标, 角色)` 做共享编码和集合聚合，同时编码现有边；GmemIII 再聚合成员 GmemII 及相对位置。角色和边偏移不能被简单的无位置平均丢掉，否则会再次退化为只识别“红色+圆形”共现。

对图片检索结果，用同一个 `psi` 编码每个实例的节点内容与匹配质量，形成 `v_j = psi(h_j, score, coverage, geometry_error, level)`，再做固定维度池化，例如

\[
 z(x)=\left[\frac{\sum_j q_jv_j}{\epsilon+\sum_j q_j},\;
                \operatorname{maxpool}_j v_j,\;
                \text{各层可评估/未决统计}\right],\qquad
 \ell=W_{cls}z+b.
\]

q_j 为非负、定义明确的匹配质量权重。空集合使用显式空响应/未决表示，max-pooling 不返回负无穷。优先按层级分别聚合后拼接，防止大量 GmemII 淹没少数实体响应。对同一实例的重复匹配先去重或限额；绑定的三模态需按角色组合，不作为三份独立样本反复计票。加权均值也不自动消除部分节点重复带来的偏差。

这样分类头维度只与 d、层级数和 C 有关，与 N(t) 无关。例如 d=256、125 类的单个线性矩阵约 128 KB；节点内容缓存仍随 N 增长，不能称整个系统恒定内存。若缓存 `h_j`，键需包含节点内容版本和 `phi` 参数版本；训练更新 `phi` 后不能继续使用旧 embedding 缓存。

当前离散检索不提供完整可微路径。可以先冻结 CNN/图/检索，只训练共享读出编码器与分类头；之后再设计监督图更新。分类损失更新 `phi` 不等于已通过反向传播优化二进制索引、Gmem 拓扑或节点创建规则。

### 3.4 方案 C：类别原型或节点—类别稀疏关联

在方案 B 的固定向量 z 上，为每类维护训练样本均值/多个子原型，用距离产生分数；或者维护每个节点对少量类别的关联计数，按图片激活聚合。这便于增量更新、可解释性较强，可作线性头的对照。

单个 GmemIII 节点不应被强制独占一个类别；类别原型更新要按独立样本去重，防止一图多个相似节点重复增加类别证据。关联表的最坏情况仍可能为 `O(NC)`，必须记录稀疏度。类别均值也可能丢失类内多样性，不能假设比监督线性头更准确。

### 3.5 图持续增长时的训练与评估协议

建议采用小阶段交替，而不是每新建一个节点就重建整套分类模型：

1. 用训练图更新记忆，得到快照版本 t；类别标签不从测试集流入记忆。
2. 冻结 t，查询当前训练批及有代表性的训练回放样本，生成读出特征。
3. 更新线性头或共享集合读出；旧类回放用于控制遗忘，验证集用于超参数与置信度校准，不写入图。
4. 保存 `图版本 + 特征合同 + 索引配置 + ID/列映射或 phi 版本 + 分类权重 + 类别表 + 优化器状态 + 划分`。
5. 测试只查询固定快照，不调用 learn；报告新增节点量、无激活率、检索截断率与分类指标。

单目标分类使用 softmax/交叉熵；多标签使用独立 sigmoid/二元交叉熵。新增类别时输出维度和概率归一化也会变化，不能沿用“零初始化新增节点列保持概率”的结论，需要类别增量训练和旧类回放。

冻结快照线性探针回答“当前图表征能否判别”；持续更新评估回答“图增长时能否保持判别能力”。两种问题应分开报告。当前仅 3 个稳定实体，推荐先以 GmemII + 候选/稳定 GmemIII 分层读出，不能等待大量稳定节点后才开始搭建评价闭环。

## 4. 推荐下一步顺序

| 优先级 | 工作 | 选择依据 |
| --- | --- | --- |
| P0 | 关系变体索引与递增 ID；记录同 episode 新节点来源 | 关系阶段已接近匹配；需控制无益增长 |
| P1 | 相似度签名剔除 gate-only 差异、静态索引增量维护、桶级共享检查 | 同时改善全局查询和粗筛构建成本 |
| P1 | 冻结快照的稀疏线性分类基线及正确数据划分 | 用实际判别指标约束后续算法修改 |
| P2 | 对高负载桶建立保守自适应分裂与布局索引 | 需要先记录桶占用和候选耗时，不能仅追求唯一编码 |
| P2 | 连续数组表示、CPU 编译并行 / 单 GPU 批处理 | 消除主要扫描浪费后再放大并发，避免进程复制整图 |
| P3 | 共享结构编码与固定维度集合分类头 | 支持长期节点增长和新节点内容迁移 |

结论：相同粗编码应由候选桶与可检测的层次差异处理；树状索引可行，但不能保证所有查询不分支。多核可行，当前先减少关系全表扫描和重复索引工作更有依据。增长图不要求分类头无限扩展；可先以可扩展稀疏线性头建立基线，再转为共享内容编码的固定维度读出。
