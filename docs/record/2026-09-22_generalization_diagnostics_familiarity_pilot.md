# 泛化诊断完善与熟悉度算法先导实验

日期：2026-09-22。依据 [泛化实验审查](2026-09-22_recall_generalization_experiments.md)、[长期训练准备度审查](2026-09-21_large_training_readiness_review.md) 和 [熟悉度算法讨论稿](../algorithm/Alg_FamiliarityGuidedGraphLearning.md)。本轮修改代码、运行小样本实验，不调整检索门限，不进行性能专项优化。

## 1. 结论与完成范围

**值得继续投入局部对应和差异归因实验，但目前没有证据支持直接启用差异驱动的自动记忆更新。** 实测同一训练对象原图、平移和亮度变化可找回；缩小 5% 和小块遮挡即不能找回。熟悉度探针在后二者上主要输出未知，尚不能稳定识别“同一个实体只有局部不同”。因此本轮实现的是冻结图的投入价值检验，而非宣称完成整套非均匀学习率优化器。

已落实的改进包括：逐对象查询持久化及拒绝原因分解、分类头强/弱证据对照、未决关联状态管理、完整训练回查的分类指标、检测漏检统计、恢复/重放一致性入口，以及六种扰动的三状态热力图。Notebook 相关开关均默认打开，执行 Run All 即依次生成结果。

仍未实现自动实体合并、稳定核心/可选成员学习、双向输入覆盖、多尺度结构检索和差异驱动的图参数更新。这些不是靠放宽阈值即可安全补齐的内容。

## 2. 代码修改细则

### 2.1 保存从底层响应到类别拒绝的诊断

`query_split` 对 readout_fit、validation、test 分别保存 `*_queries.jsonl`、`*_cache.pt`、`*_summary.json`。逐对象包含图版本、五模态有限像素/门控像素、区域及实体候选数、精验 trace、初始稀疏查询 trace、接受实体和类别预测；每处理完一个对象立即追加 JSONL，便于中断后审查。

类别拒绝原因区分 `no_accepted_entity`、`class_score_below_threshold` 和 `class_margin_below_threshold`。`search_complete=False` 仍代表近似搜索未证明穷尽，不解释成已经证明对象不存在。

分类头保留原 accepted 证据，并新增独立的 weak 对照：每类从已有 L3 精验 trace 中选取最高分数乘覆盖率的假设，保留其分数、可评估覆盖、匹配覆盖、归一化几何误差、拒绝标记和搜索未完成标记。维度仍是 $6C$，不随实体数量增长。弱假设只用于分类诊断，不能授权图写入。

两种分类头分别记录 `feature_source`、独立保存检查点；缓存与分类头来源不同会拒绝评价。Notebook 在拟合集缺类、特征完全相同或缺少独立 validation 时打印并保存跳过原因，继续其它实验。仅用 readout_fit 拟合、validation 选择训练轮次，test 不参与选择。当前 test 已在历史分析中被查看，后续正式结论需另留最终评价集。

### 2.2 未决关联管理

新增 `pending_associations.py`，按对象来源去重：

- 无竞争候选的几何修复历史记为 `resolved_local`，不再独立阻止视觉确认。
- 真实候选保留 `pending`；独立且可比较的观察累计支持或反对。缺失、不可评估、稀疏漏检记未知，不作反例。
- 足够支持且没有反对可 `confirmed`；足够反对且没有支持可 `rejected`；混合证据继续未决。
- 候选版本变化或局部角色缺失记 `stale`，不继承旧版本的支持；版本变化会使已确认的区域关联重新待验证。
- 唯一确认且其它竞争者全部驳回，才确认区域关联；实体层仅保存独立精验支持的共同关联，不因检索漏掉竞争者而自动驳回它。

新写入记录保存 `local_semantic_id`，便于把历史候选放回实体局部坐标精验。旧检查点缺失此字段的真实 pending 不能凭空恢复对应，后续复查会保留为 stale，需要补充角色配准。确认只表示关联证据，不自动重定向共享 GmemII 或合并 GmemIII。

`maintain_pending()` 是显式维护步骤：复制元数据、规范状态、仅在变化时增加图版本，使旧分类缓存失效。查询/validation/test 不调用学习。几何重建的阶段耗时现在汇总首轮和重试，避免首轮计算从统计中消失或递归耗时被重复计入。

### 2.3 回查、检测与持久化

训练回查同时报告目标实体命中和最终类别是否正确，二者不再混为一个指标。检测保留兼容字段 `unresolved_proposals`，并提供含义明确的 `incomplete_search_proposals`、逐候选读出拒绝原因、每类 TP/FP/FN 和召回率；无检测输出时仍会正确统计漏检。

Notebook 最后保存、重载记忆，检查图版本/节点数/账本一致、重复来源不增加证据，以及重载前后查询结果在数值容差内一致。所有结果汇总到 `all_results.json`。

## 3. 新算法的可运行探针

### 3.1 实现的数学含义

探针不要求完整实体先被接受，从包含被拒绝候选的 L3 trace 取最佳候选位置，再运行原空间精验器取得槽位对应。它复用现有候选产生流程，尚未实现独立的稳健 family 配准器。

按来源 family 聚合槽位，令 $v_f$ 为能取得对应的槽位权重比例，$s_f$ 为对应响应加权均值，$q_f$ 为已存成员可靠性，$u_f$ 为候选竞争引入的不确定性：

$$
F_f=q_fv_f(1-u_f)s_f,\quad
D_f=q_fv_f(1-u_f)(1-s_f),\quad
U_f=1-q_fv_f(1-u_f).
$$

三者是工程诊断量，不是经校准的概率。当前 $q_f$ 来自存储模板，尚不能充分刻画本次遮挡和采样质量。至少两个可靠 family、足够空间跨度和无明显候选竞争，才允许提出“熟悉核心存在”的建议。无法对应时优先输出未知。

每个 family 在其预测槽位邻域投影一次，重叠按 family 数归一化，避免 grad/curv/aps/ori 重叠把热度重复放大。每例保存输入、熟悉/可靠差异/未知三图，以及 NPZ 原始数值、JSON 查询证据和变更区/非变更区统计。

**热力图只覆盖候选模板支持，未覆盖的输入位置为未知。** 它尚不能检测模板之外所有新增前景，也没有完成 $C_{O\to H}$。`reinforce_known` 等输出只是只读建议，不增加任何独立学习证据。

### 3.2 对照与判定

默认每次选最多三个已学习对象，优先不同类别，分别测试原图、水平平移 4 像素、缩放 0.95、亮度乘 0.85、局部均值块遮挡和交换对角象限。查询不接收目标实体 ID 或类别，二者仅用于事后评分。遮挡位置只用于评价热图，不作为算法可见的遮挡答案。

布局打乱保持局部像素但改变组合，只是结构对照，不能保证变成另一个语义类别。投入判断必须同时考虑正例的缩放/遮挡与布局对照，不能仅凭原图和平移成功就判断新算法值得自动更新。

## 4. 已完成的小样本实测

### 4.1 环境与原始产物

使用已有 `voc2007_20260921_231411_853393/memory.pt`，34 个训练实体。对工作副本执行 pending 维护，图版本从 34 变成 35；未增加节点、未增加独立观察，未覆盖原检查点。

当前工具进程 CUDA 不可用，实际测试使用 consciousLinux Python、CPU、两个 PyTorch 线程。绘图时进程预加载 conda 的 `libstdc++.so.6` 以解决工具进程的 CXXABI 冲突，没有修改系统环境。Notebook 仍优先选择可用 CUDA。

完整先导产物：`results/supervised_graph/generalization_pilot_20260922/`，其中 `run.py` 可复现，`pilot/summary.json`、逐例 JSON/NPZ/PNG 保存最终程序输出。先导规模为 **一个 dog 对象（003671/0）的六个控制条件，加一个独立 validation car 对象**，不是全数据集成绩。

### 4.2 熟悉度实验

| 条件 | 找回目标实体 | 可靠 family 数 | 平均熟悉 F | 平均差异 D | 平均未知 U |
| --- | --- | ---: | ---: | ---: | ---: |
| 原图 | 是 | 3 | 0.999989 | 0.000011 | 0 |
| 平移 4 像素 | 是 | 3 | 0.999891 | 0.000109 | 0 |
| 缩放 0.95 | 否 | 0 | 0.060439 | 0.015951 | 0.923609 |
| 亮度乘 0.85 | 是 | 3 | 0.999988 | 0.000012 | 0 |
| 局部遮挡 | 否 | 0 | 0.030672 | 0.006963 | 0.962365 |
| 交换对角象限 | 否 | 0 | 0.030672 | 0.006963 | 0.962365 |

原图/平移/亮度建议 `reinforce_known`；其它三种建议 `insufficient_correspondence`。缩放最佳候选变成实体 16，遮挡与布局打乱均变成实体 9，目标实际为 0。这说明后三种条件的热图来自错误的候选解释，不能拿它们更新目标实体。遮挡和布局负对照结果相同，也说明当前还无法稳定区分局部遮挡和结构冲突。

另一个限制是热图支持很稀疏：原图约覆盖输入的 1.63%，遮挡条件约 0.76%；遮挡区域内没有非零可比较支持，`difference_changed=None`。所以当前尚无“差异热度准确落在修改部位”的正面证据，不能把未知位置视作差异为零。

最终投入判定为 `fix_scale_and_partial_correspondence_before_learning`。这不是证明非均匀学习率无效，而是其前提——可靠的同实体局部对应——目前没有通过最小控制实验。

### 4.3 留出失败定位

validation 图 000007 的 car 对象没有接受实体，最终拒绝为 `no_accepted_entity`。已有 932 个接受的区域位置匹配及 101 个实体候选位置，因此不能把失败归因于全部 CNN/L2 响应为零。

最终 trace 中 25 个 L3 模板的最佳假设均未接受；拒绝理由可重叠：score 24、matched_coverage 23、evidence_conflict 23、evaluable_coverage 20。最高分约 0.695 的候选匹配覆盖约 0.801，但可评估覆盖只有 0.093，仍不能据此建立实体身份。候选搜索也存在预算截断；当前结果不能证明其它位置没有合适实体。

这支持优先改进候选局部对应和可见性解释，不能据单样本断言放宽某一个门限就会提升泛化。weak 特征可能保留比全零接受证据更多的信息，其分类收益仍须看 Notebook 的独立拟合/验证对照。

### 4.4 pending 维护

清理出 328 条无竞争候选的修复历史；保留 279 条真实区域候选记录，31 个实体仍有未决关联。当前没有新增独立观察，不能期待清理元数据就让这些实体变成视觉稳定核心。

## 7. 下一步投入建议

1. **先改局部对应**：从多个可靠 GmemII family 保留若干位置假设，利用分散锚点共同确定候选，记录目标是否在候选中、是否被粗筛截断、是否只在整体验证被拒绝。不要让单个区域或错误最佳候选决定差异图。
2. **再处理轻微尺寸变化**：优先试少量归一化视图尺度或候选条件下的局部尺度配准；继续复用 Gmem/Gpos 存储，所有尺度结果回到统一坐标。正例覆盖提升必须同时检查布局负例的误接受。
3. **区分遮挡与替换**：补输入到模板的反向 family 覆盖和未解释前景，并对门控不可评估、出视野、遮挡等原因分开记录。未知不能直接转换为负证据。
4. **先验证差异定位再启用非均匀更新**：要求已知局部修改下，正确候选仍被锚定，变更区差异高于未变区，遮挡优先未知，旧对象回查不退化；至少在多个对象及独立视图重复。
5. 条件通过后，先让差异图控制候选建档/复习优先级，再接入本实体的可选成员及更新幅度。共享 GmemII 原型保持受保护，独立来源支持计数不按学习率放大。

本轮不能给出准确率提升承诺，也没有训练新算法后与旧算法比较的 A/B 成绩。可执行诊断已经把下一步问题缩小到可以验证的局部对应、尺度和可见性解释。
