日期：2026-09-22。检查 Notebook 保存输出及 `results/supervised_graph/voc2007_20260921_231411_853393/training_recall.json`；未修改代码、未重新训练。Notebook 当前有两个编号为“9”的小节，本报告同时审查无框检测和冻结记忆回查。

## 1. 结论

**34 个训练对象全部能从最终记忆中找回各自实体；但已测的 57 个留出对象全部未决，无框检测也没有输出。** 这明确改善了上次“只有三个训练对象抽查”的证据范围，同时说明目前的主要瓶颈已是跨图片的判别与结构泛化，而非训练对象无法持久保存。

这不是运行异常：已检查的单元没有保存异常输出。也不是“57 个对象全被分到错误类别”，而是当前读出拒绝给出类别。

## 2. 冻结记忆回查

回查使用 graph_version=34，覆盖此前学习的全部 34 个对象：

| 指标 | 结果 |
| --- | ---: |
| TARGET_HIT | 34/34，100% |
| 每次接受的实体列表恰好为目标实体 | 34/34 |
| SAME_CLASS_ONLY / WRONG_CLASS_ONLY / NO_HIT | 均为 0 |
| structural_fallback | 34/34 |

这是正常视觉查询，未调用学习或通过账本直接返回“命中”，因此可确认本轮 34 个已知框训练输入的最终记忆保持性。

但回查函数记录的是实体命中，不执行类别读出的最终接受门限；不能直接把它写成“训练分类准确率 100%”。另外，每次查询都调用了输入区域结构回退，这只证明回退参与，不证明其中每次初始稀疏查询都完全无命中；弱分数或竞争也会触发回退。

回退只使用输入分区，不读取目标实体 ID 或类别。但重现相同输入时，重新分割得到的锚点容易与写入时一致，所以原图回查比新视角、新光照或新实例识别容易得多。

## 3. 第 8 节：留出查询

当前 QUERY_IMAGE_LIMIT=20，限制的是每个划分的原图数，不是对象数。RUN_HEAD_FIT=False，没有执行分类头拟合；下表是现有类别证据读出的结果：

| 划分 | 对象数 | cat / dog / car | 准确率 | 宏 F1 | 接受覆盖率 | 未决率 |
| --- | ---: | --- | ---: | ---: | ---: | ---: |
| validation | 26 | 6 / 6 / 14 | 0 | 0 | 0 | 100% |
| test | 31 | 6 / 9 / 16 | 0 | 0 | 0 | 100% |

混淆矩阵的所有计数都在 REJECTED_OR_UNRESOLVED 列；unresolved_rate=1.0 进一步表明全部是 UNRESOLVED。accepted_accuracy=None 表示没有可计算接受准确率的样本，不是程序漏算。

readout_fit 也运行了查询，但输出只有资源统计，没有准确率或逐对象预测明细，不能推断其结果与另外两个集合相同。

### 3.1 目前不能从汇总结果确定的事情

UNRESOLVED 可能来自：

1. GmemIII 没有接受的实体匹配。
2. 存在接受实体，但类别读出分数过低。
3. 类别最高分与次高分差距不足。

`ClassEvidenceReadout.encode` 只把已接受 GmemIII 匹配转为类别证据，读出分数还乘以覆盖率和几何误差惩罚。因此不能由“准确率 0”直接断言“所有底层特征响应都是 0”，也不能直接断言“CNN 没有学到特征”。

留出 caches 当前仅保存在内核运行变量中，目录未保存逐对象查询缓存/trace；本次仅凭汇总无法进一步分解以上三类原因。

## 4. 无框检测

测试在官方 test 划分的一张图片上执行，graph_version=34：

- 输出检测列表为空。
- dog AP=0；cat/car AP=None，表示该次评价没有相应类别真值，不能解释为这两类 AP=0。
- 当前单图有效类别平均 AP=0，不是 VOC 全测试集 mAP。
- dog proposal_recall=1.0，IoU 门限为 0.5。说明本图每个被评价的 dog 真值至少有一个候选框达到覆盖标准；不能据此认定所有候选框都精确。

### 4.1 两个字段容易误读

`proposal_search_complete=True` 仅说明配置内的滑窗候选没有被预算截断，不证明已经穷尽所有可能框或完成实体检索。

`unresolved_proposals=211` 在当前代码中统计的是每个候选的 `search_complete=False`，**不是统计 211 次分类失败**。稀疏检索即使找到正确实体，search_complete 仍可能为 False。没有检测框是另一个独立事实，不能用这个计数解释具体拒绝原因。

`errors` 两项为 0 是因为没有输出框，当前字典只统计输出框中的误检/重复，并不统计漏检。应增加 FN、检测召回率及各阶段拒绝计数，避免“错误为 0”造成误解。

本次框候选覆盖已有正面证据，因此不应优先增加滑窗数量。已知框的留出识别也全部未决，先解决它更容易隔离问题。

## 5. 为什么呈现“原图能记住，新图无法判别”

以下是代码与结果共同支持的解释方向，不是逐样本 trace 已确认的唯一原因：

- 记忆只有 34 个标注观察模板，全部独立支持为 1，上次批量没有实体复用更新。类别内多姿态、多背景、多实例覆盖有限。
- 当前实体验证以固定局部外观和相对像素布局为主，主要支持平移。框归一化不能消除姿态、部件比例、局部形变和锚点变化。
- 多数观察通过本地几何重建后存入，利于解释原输入，但跨观察共享/巩固不足。存在典型的实例记忆与类别概念之间的能力缺口。
- 分类读出只有已接受 GmemIII 的证据。若结构验证稍不满足就不给高层证据，GmemII 中可能已有的局部相似部件也无法帮助分类。
- 未决关联尚无完整退出/巩固流程，多次出现的共享结构未被验证为稳定核心。

两组指标的强烈差异与模板对具体输入过于敏感相符，但不能仅凭这 57 个对象断言模型结构不可行。也不能假设只增加训练量就必然解决。

## 6. 建议下一步实验与改进顺序

### P0：保存留出失败漏斗

在已计算的 readout_fit/validation 缓存上先保存逐对象 scores、entity_id、状态和图版本；对少量失败样本重新查询并记录：

1. L1 有效响应、L2 弱命中和接受命中。
2. L3 候选数量、最优失败模板及拒绝原因。
3. 原始结构分数、覆盖、几何残差、角色冲突。
4. 类别读出惩罚前后分数与最高/次高差距。
5. 稀疏路径和结构回退各自的结果。

由此区分候选没找到、结构精验没通过和分类读出拒绝，针对实际失败环节修改，不统一降低所有阈值。

### P0：建立从记忆到泛化的难度阶梯

固定同一已学对象，依次只改变一项：小平移、框边界轻微扰动、尺寸变化、亮度/颜色、小遮挡。使用冻结图比较目标命中与位置残差，再测试同对象不同真实视角、同类不同实例。

若轻微框扰动即失配，应先修锚点/归一化与部件对应；若扰动稳定但同实例新视角失败，考虑结构变换；若同实例稳定而跨实例失败，再检查类别证据和模板覆盖。增强样本不能冒充独立观察支持。

### P1：补齐巩固与层级分类证据

- 完成 pending 的确认/驳回/过期机制，区分历史几何修复与当前有效歧义。
- 用独立观察形成稳定核心与可选成员，按可靠性而非碎片数量计算结构覆盖。
- 在已接受实体之外，考虑为分类头提供“弱实体分数、可靠部件覆盖、几何残差与缺失证据”，但这些弱证据不能直接作为实体复用/写入的依据。
- 若所有留出特征向量都因无实体接受而相同，训练线性分类头不能恢复已经丢失的信息；先检查特征差异和非零覆盖，再开启 RUN_HEAD_FIT。

### P1：正例改进必须伴随负例

加入同色异形、同形异色、部件相同但布局错误以及未学习类别。监测误接受，防止为了提高留出覆盖而把错误结构都认成已知实体。

### 后续：分段扩大观察覆盖

先让少量独立观察产生可解释的复用，或验证新增类内模板确实提高 validation 覆盖，再分阶段增加数据量。测试集已被查看，后续调参应使用 validation；不要反复根据当前 test 结果选方案，再把同一 test 当作未使用的最终评价。
