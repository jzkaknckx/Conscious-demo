# 完整实验审查：结构冲突、弱证据分类与熟悉度对应

日期：2026-09-23。审查运行 `results/supervised_graph/voc2007_20260922_222716_908742/`、监督 Notebook 保存输出及相关实现。本轮仅分析、编写报告并对已有缓存计算简单对照；未修改模型、未重训、未调整阈值。

## 1. 主要结论

本轮证明了**原图记忆、完整实验流程和恢复一致性正常**，但仍未证明跨图实体泛化或有效的三类判别能力。

最值得优先处理的三项问题是：

1. **局部匹配冲突的一票否决。** 汽车平移和亮度扰动中，正确实体已经进入候选，分数与覆盖都高，但仅因 `evidence_conflict` 被拒绝。这是可以定位到具体算法步骤的失败。
2. **分类头没有带来已验证的学习收益。** weak 分类头把 validation/test 的全部对象预测为 car；约 52% 的测试准确率与固定预测 car 相同。相同种子的未训练分类头也给出相同的类别预测。
3. **差异学习前提尚未成立。** 三个对象缩放 0.95 和局部遮挡全部失配；探针还会对被结构精验拒绝的候选建议 `reinforce_known`。当前应继续保持只读，不接自动记忆更新。

建议下一轮先修对应与诊断的一致性，再做小样本控制实验；暂不直接扩大图训练规模。

## 4. 弱证据分类头：约 52% 并非三类判别成功

### 4.1 实际结果

| 指标 | validation | test |
| --- | ---: | ---: |
| 对象数 | 26 | 31 |
| 准确率 | 53.85% | 51.61% |
| 宏 F1 | 0.2333 | 0.2270 |
| cat / dog / car 召回率 | 0 / 0 / 1 | 0 / 0 / 1 |
| 预测类别分布 | 全部 car | 全部 car |

validation 有 14/26 个 car，test 有 16/31 个 car，所以准确率恰好等于相应集合中 car 的比例。平衡准确率均为 1/3。

`coverage=1` 也不能解读为实体识别覆盖提升：`SupervisedExperiment.evaluate` 对训练头输出直接 argmax 并标记 PREDICTED，没有应用未知类别拒绝或原实体精验门限。

### 4.2 最佳检查点实际上只有一次优化器更新

拟合集共 27 个对象，小于 batch_size=32，每个 epoch 只有一个参数更新。训练执行 epoch 0–5，validation loss 从 0.88472 单调升到 0.90169，随后早停并恢复 epoch 0；保存的 Adam step=1 证实最终采用的是第一次更新后的参数。

本轮只读重建相同 seed=0、相同维度的未训练线性头，并在原缓存上前向计算。其 readout_fit、validation、test 预测也全部为 car。**现有指标没有体现相对于初始化的类别预测改善。** 不能把当前结果当作充分训练后的 weak 表征上限，也不能简单推断增加 epoch 就会有效。

训练代码已经使用类频率加权交叉熵，问题不是完全遗漏了类别平衡。拟合集类别为 cat/dog/car=9/12/6，而 validation=6/6/14、test=6/9/16；三者类别比例明显不同，且每组对象来自仅 20 张图，独立样本量更小。

### 4.3 weak 向量有变化，但需要验证判别性

本轮额外做了不训练的缓存对照。以下均为事后诊断，不能根据 test 选择其中最优公式再宣称泛化提升：

| 固定规则 | validation 准确率 / 宏 F1 | test 准确率 / 宏 F1 |
| --- | --- | --- |
| 全部预测 car | 53.85% / 0.2333 | 51.61% / 0.2270 |
| 全部预测拟合集多数类 dog | 23.08% / 0.1250 | 29.03% / 0.1500 |
| 每类 weak score 取最大 | 53.85% / 0.4231 | 58.06% / 0.3996 |
| 每类 score × matched coverage 取最大 | 57.69% / 0.4286 | 48.39% / 0.3338 |
| 再乘 evaluable coverage | 34.62% / 0.2792 | 29.03% / 0.2626 |

这些规则使用缓存内已经选好的类候选，并未重新搜索。结果说明 weak 证据中有一定区分信号，当前线性头没有有效利用；同时，简单乘上可评估覆盖并不能自动改善分类。

84 个 weak 向量的“拒绝”和“搜索未完成”通道均为常量 1，三类共六个常量维度；其线性作用可以被偏置吸收，本身不能提供类别区分。候选通常只有较低可评估覆盖，分数还受模板大小、可见区域与候选选择影响，不能直接称作类别概率。

缓存分析脚本与结果位于 `results/supervised_graph/review_20260923/`，可重复计算，没有重训模型。

### 5.1 汽车平移/亮度：正确候选存在，局部证据冲突阻止接受

| 条件 | 目标实体分数 | 可评估覆盖 | 匹配覆盖 | 几何误差 | 唯一拒绝原因 |
| --- | ---: | ---: | ---: | ---: | --- |
| 平移 | 0.9071 | 约 1 | 0.9776 | 1.0 | evidence_conflict |
| 亮度 | 0.9600 | 约 1 | 1.0 | 2.0 | evidence_conflict |

`SpatialStructureMatcher.evaluate` 先为槽位独立选择局部最佳响应，然后检查是否占用同一证据点。若同模态槽位落在同一位置，而模板预期位置相距超过 0.5 像素，就设置 conflict，拒绝整个实体；当前没有冲突后的组合重分配。

因此这里的 conflict 可能来自多个邻近槽位选择同一个局部峰值，并不自动证明对象身份冲突。**是否存在可行的次优联合分配，需要新增冲突对和备选位置诊断才能确认。** 不应直接删除防重复占用约束，否则错误布局可能复用同一个峰解释多个部件。

### 5.2 探针与精验结论不一致

汽车平移、亮度条件下，探针仍输出六个可靠 family、熟悉度约 0.940/0.965，并建议 `reinforce_known`。原因是探针根据 family 的平均响应、可评估性及跨度决策，没有把精验器的 evidence conflict、冲突质量比例和关系一致性作为同等门槛。

这说明热图可以作为局部相似性描述，但目前不能用于授权旧实体更新。应区分“局部特征熟悉”与“实体关联可信”；即使部分实体允许不完全匹配，也应先证明被接受核心的联合对应无冲突。

### 5.3 候选选择偏爱少量可见证据

探针按 `score × matched_coverage` 排序，未纳入可评估总量。汽车遮挡下，目标实体仍有约 1 的可评估覆盖、0.9416 匹配覆盖和 0.5272 分数，只因分数与冲突未通过；探针却选择了实体 16，其 family 平均未知度约 0.9236。

这表明“遮挡后没有熟悉核心”有一部分可能来自错误候选选择，而不是输入完全丢失熟悉证据。需要保留多候选并比较可靠支持量，不能对错误最佳候选的热图作实体更新解释。简单全局乘 evaluable 的分类对照成绩不佳，也说明身份候选选择与类别读出不宜共用未经验证的单一乘积公式。

### 5.4 热图还没有验证差异定位

原图的模板支持仅覆盖约 1.63%、3.29%、3.17% 的视图。三个遮挡条件的 `difference_changed` 全为 null，表示变更区没有非零可比较热图支持，不是“遮挡区没有差异”。部分错误候选的大多数部件不可比较，探针自然给出高未知度。

少数 U 约为负 $10^{-16}$，属于浮点舍入误差；可在显示和统计边界裁剪到 $[0,1]$，不是本轮失败主因。

## 6. 无框检测

图 000001 有一个 dog 真值：211 个候选全部 `no_accepted_entity`，输出检测框为零，TP=0、FP=0、FN=1、召回率=0。候选框 recall@0.5=1，说明至少有一个框覆盖目标。

当前应先解决已知框上的结构识别，而非增加滑窗数量。此检测流程仍使用原实体证据读出，没有接入已拟合 weak 分类头；不能把检测失败表述为 weak 分类头检测失败。也不能直接接入一个全预测 car 的分类头就期待检测提升。

`incomplete_search_proposals=211` 与 `no_accepted_entity=211` 是不同统计：前者表示候选内部搜索未证明完整，后者才是本次分类拒绝原因。

## 7. 建议的改进顺序与验收条件

### P0：完善冲突诊断，并统一“熟悉”与“可更新”的语义

记录冲突涉及的槽位、modality、family、预期坐标、实际位置、响应及备选位置；保存冲突个数、可靠权重比例和关键角色是否受影响，而非只有一个布尔值。

探针输出拆成局部熟悉状态与身份关联状态。冲突未解决时可显示熟悉图，但不得给出具有更新含义的建议。候选按可评估总量、独立 family 数、空间跨度、冲突和分数分层选择，保留少量竞争者，而不是只保留一个最高乘积分数候选。

验收：汽车平移/亮度失败能解释到具体冲突对；探针不再对未验证的对应建议更新；训练 34 对象回查与布局对照保持原有结果。

### P1：对冲突局部做联合分配

保持 Gmem/Gpos 大体结构不变，只替换精验中的局部证据分配：为冲突槽位保留少量响应候选，在冲突连通分量内做带不匹配选项的匹配。代价同时考虑特征响应、位置偏差与几何关系，明确哪些同源槽位允许共享，哪些独立角色必须互斥。共享例外须基于存储角色语义，不能一律允许同 family 重用证据。

若没有可靠一致的分配，保持未决；不要用忽略所有 conflict 来换覆盖率。局部二部匹配可作为基础，但加入成对几何约束后不再是纯线性指派，需受限搜索和精验复核。

验收：正确平移候选可以通过合法的次优分配恢复；同色异形、局部峰重复、交换布局等对照不被错误接受。这项优先于全面降低 graph 阈值。

### P1：区分尺度候选生成失败与精验失败

对已知扰动，诊断阶段分别测试：普通候选、目标模板在真实变换下的已知位置、真实变换附近的局部精验。已知目标与变换只用于离线定位问题，不得进入正常预测或记忆更新。

在 0.95 缩放下，若正确位置没有进入候选，应改善跨 family 的位置投票；若位置正确但槽位坐标不适配，再加入少量尺度假设。可以先在查询视图上做尺度对照，或令 $T(x)=sx+b$，统一缩放成员坐标和关系约束，结果映射回原图。训练池不必同时重写。

验收：多个对象的轻微尺度扰动稳定改善，同时检查错误组合的误接受，不能只展示一个成功对象。

### P1：把分类头对照做成真正的学习有效性实验

- 显示 epoch -1 的初始化成绩、每轮拟合/验证 loss、宏 F1、各类召回率、预测类别直方图和实际更新次数。
- 增加按原图独立的类别覆盖，报告图像数和对象数；防止只看一个由 car 占优的验证窗口。
- 标准化参数只在 readout_fit 上估计并随分类头保存；常量维度显式处理。比较多个固定随机种子，避免一次随机初始化主导判断。
- 以已有简单 weak 规则、拟合集多数类和未训练头作基线。早停标准在验证前定义，可考虑宏观类别指标与 loss 的联合约束，不能靠 test 选训练轮次。
- 分类 argmax 和带拒绝的识别分开报告；未知类、低支持量和身份冲突仍需单独的校准机制。

验收：在独立验证中宏 F1 和非多数类召回明显优于固定类/初始化基线，并在多个划分或随机种子上稳定。当前 57 个留出对象已被多次审查，正式结论需要预留新的最终评价窗口。

### P2：对应可靠后再接入差异学习与跨观察巩固

先补输入到模板的反向覆盖及未解释前景区域；对遮挡、门控不可评估、角色缺失和真实替换分别标记。设计确实覆盖已存支持的局部替换对照，并同时报告变更区、非变更区及无法比较区域的比例。

对应与差异定位通过后，先让热图控制候选建档/复习优先级，再考虑本实体关系的差异化更新。共享 GmemII、已有核心及独立来源计数保持保护。随后使用新窗口或同实例独立观察验证 pending 退出；重复原来 34 个来源不能验证巩固。

## 8. 下一轮最小实验建议

1. 固定当前 34 对象图，先围绕汽车平移/亮度两个可解释失败进行冲突诊断和联合分配验证。
2. 在当前三个对象上做分阶段尺度/遮挡诊断，补“候选没有召回”与“正确候选未通过精验”的分项指标。
3. 利用现有缓存先完善分类头初始化基线与训练监测；扩大独立拟合/验证窗口前明确判定指标。
4. 完成上述检查后，加入新的独立训练来源，观察是否出现真实的实体更新与 pending 支持，而非只增加实例节点。
