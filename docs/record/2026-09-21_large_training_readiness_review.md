## 4. 最明显的功能缺口：未决关联没有完成或退出机制

代码目前向 pending_reuse 添加记录，再以历史记录是否非空计算 reuse_unresolved；尚没有确认、驳回、失效或消除历史待决状态的处理器。visually_confirmed 又要求 reuse_unresolved=False。

因此，多数本轮实体即使以后获得重复支持，也可能一直被历史未决记录挡在视觉确认之外。进一步发现：586 个 local_geometry_repair 成员中，328 个候选列表为空，但这些记录也作为未决关联保留。**“曾经做过几何修复”和“当前还有竞争关联待解决”应拆开。**

大规模训练前需补齐：

- 几何修复历史作为审计，不自动形成永久 pending。
- 只有真实竞争候选才形成待决关联；保存候选版本、来源及待验证条件。
- 明确 pending → confirmed / rejected / stale 的状态转移。确认后转移来源与证据，驳回后保留当前本地结构；同一来源不能两边同时计数。
- 有效未决成员与历史已解决记录分开统计，实体的视觉确认只受当前未决核心关系影响。
- 版本过期候选重新验证；不能用当初的分数直接合并当前已变更模板。

这是功能闭环问题，优先于吞吐优化。
