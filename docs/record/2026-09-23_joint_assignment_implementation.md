# 局部联合分配、熟悉度判定与分类头诊断改进

日期：2026-09-23。依据 [完整实验审查](2026-09-23_full_experiment_review.md)。本轮不改变 Gmem/Gpos 存储层级，不调整特征、匹配或学习门限；对局部对应算法与实验流程进行修改，并执行针对性验证。

## 1. 本轮修改

### 1.1 用受限联合分配修复局部证据争用

新增 `src/nns/memorygraphs/local_assignment.py`，由 `SpatialStructureMatcher.evaluate` 调用。原有独立最佳响应仍是第一步；没有冲突时不运行组合搜索。

发生冲突时：

1. 按模态和选中证据坐标找出所有争用槽位，保留每个冲突对的预期位置、实际位置与响应。修复原检查只记住最后一个占用者、可能漏掉先前冲突的问题。
2. 将冲突槽位分成连通分量。每个槽位保留局部窗口中至多 K 个达到原 recall 门限的候选；未冲突槽位保持原分配。
3. 在每个分量中使用有界束搜索，按槽位权重与响应对数之和选择组合，同时检查证据互斥与可确定的几何约束。其它分量当前占用的证据同样被保留，避免局部修复制造新的跨分量重复占用。
4. 重新计算整体分数、可评估覆盖、匹配覆盖、几何误差及冲突，仍使用原门限判断接受。

局部优化目标为：

$$
\max_{a}\sum_{i\in C}w_i\log\bigl(\max(r_i(a_i),\epsilon)\bigr),
$$

其中 $C$ 为冲突分量，$a_i$ 为局部证据位置；同模态、不同预期角色保持互斥，几何约束必须通过。候选分数不超过原独立最大响应，包括浮点边界，以保留原渐进上界筛选的安全性。

默认配置：`graph_joint_assignment=True`、`graph_assignment_topk=5`、`graph_assignment_beam=32`、`graph_assignment_max_slots=16`（每个冲突分量）。配置可关闭用于对照；这些是受限搜索规模，不是放宽识别门限。

没有找到受限解时保留原冲突与拒绝结果，不宣称已证明无解；不自动删除槽位，不用缺失选项逃避证据互斥。当前不是全局最优指派，也不允许不同独立角色共享证据。合法的同位置共享保持原有语义。

`StructureMatch.summary` 和查询 trace 增加 `assignment_diagnostics`：冲突数、冲突权重、分量大小、冲突对、候选位置、修复状态与非穷尽标志。搜索仍服从已有 `SearchBudget`；没有增加单步秒数限制。

### 1.2 探针不再把局部熟悉当作可信实体关联

候选排序先区分是否已接受、可评估总量是否达标，再比较分数 × 匹配覆盖 × 可评估覆盖；保存若干竞争候选（默认 3）供审查。此为候选启发式，不是经过校准的类别概率，也没有声称它必然提高分类成绩。

输出新增 `identity_verified`、结构拒绝理由及分配诊断。局部 family 熟悉但结构未接受时，建议为 `hold_correspondence`；不再建议 `reinforce_known`。算法仍只读，所有建议都不写图。三状态数值裁剪消除浮点舍入造成的微小越界。

先导实验的投入判定现在要求身份验证通过；仅有正确候选 ID 和若干熟悉 family 已不够。候选与模板支持的局限仍保留，未实现输入到模板的完整反向覆盖。

### 1.3 增加已知变换的离线诊断

在先导实验中，用原图成功查询确定的目标位置，计算合成平移/尺度变化对应的位置，分别执行：

- 已知位置、原模板几何精验；
- 已知位置、按已知尺度变换的槽位与关系精验。

明确标为 `oracle_only`，只作为离线诊断，不参与正常候选生成、分类成绩、探针选候选或图更新。布局打乱不具有统一刚性变换，跳过此项。模板出现在 trace 中也不等于正确位置被提出，输出明确保留这一限制。

增加变更区域的 `changed_comparable_fraction`，区分“差异为零”和“该区域没有可比较支持”。Notebook 将上述指标展成表格，并保存完整 JSON。

### 1.4 分类头：训练前基线、标准化和固定种子对照

`ClassifierTrainer.fit` 默认只根据 readout_fit 估计均值/标准差，抑制拟合集中的常量维度；validation/test 不估计预处理统计。参数与 active mask 一起保存，旧分类头检查点按不标准化解释，避免改变旧权重的输入语义。

每轮记录训练/验证 loss、准确率、宏 F1、逐类召回、预测类别分布和累计更新数。epoch=-1 记录完成输入预处理后的未训练基线，并参与 validation loss 的最佳状态选择；如果训练未改善验证损失，可以明确返回初始化状态，而不是至少强行选择一次更新。

Notebook 默认执行 seed=0/1/2 三个固定对照，不按 test 选种子，每个头分别保存。另保存固定类别、拟合集多数类、weak score 和 score×coverage 的基线。分类头仍为闭集 argmax 对照，不等于增加了未知类拒绝能力或接受了 GmemIII 实体。

本轮未提高训练 epoch 上限、未调学习率、未改变早停 patience，也没有根据测试集更换选择规则。

## 3. 验证结果

产物目录：`results/supervised_graph/assignment_validation_20260923/`。工具进程使用 CPU，未覆盖用户的原始检查点。真实样本取 car 007490；开/关对照采用相同输入和同一位置。

### 3.1 真实局部精验与普通查询

| 条件 | 原分配 | 联合分配 | 观察 |
| --- | --- | --- | --- |
| 原图 | 接受 | 接受 | 原匹配保持 |
| 平移 4 像素 | 因冲突拒绝 | 接受 | 1 对冲突，2 个槽位重分配 |
| 亮度乘 0.85 | 因冲突拒绝 | 接受 | 33 对冲突拆成 27 个小分量，均完成分配 |
| 布局打乱 | 拒绝 | 拒绝 | 未找到受限解，原分数/覆盖/冲突拒绝保留 |

联合分配后的平移、亮度分数约为 0.9060、0.9597，未通过提升响应或放宽阈值制造成功。

另外对平移输入重新执行了一次**普通层级查询**，成功找回目标实体，探针身份验证通过。亮度结果仅完成已知候选位置上的精验对照，未在本轮单独复跑完整普通查询，需在 Notebook 全流程确认。

### 3.2 缩放仍有未解决问题

汽车 0.95 缩放在已知位置、已缩放几何条件下仍因 score 拒绝。说明至少这个样本的失配不能仅靠补正确位置和几何缩放解决；还需检查缩放后的 CNN 响应、采样点对应、插值和模态门控。当前没有把已知尺度接口当作已完成的多尺度检索器。

### 3.3 旧缓存上的分类头对照

使用上一轮 27 个 readout_fit 对象、26 个 validation 和 31 个 test 的固定缓存，验证新版分类头流程；这些不是新匹配器产生的特征。

| seed | 采用 epoch | validation 准确率 / 宏 F1 | test 准确率 / 宏 F1 |
| --- | ---: | --- | --- |
| 0 | 34 | 46.15% / 0.4103 | 38.71% / 0.3725 |
| 1 | 49 | 34.62% / 0.3193 | 22.58% / 0.2278 |

这不再只是“训练一次、全预测 car”的相同结果，但准确率没有超过之前固定 car 的基线，种子敏感性也明显。**不能宣布分类问题已经解决。** 新流程主要使训练行为可见、输入尺度一致、对照更可信；下一轮仍应扩大独立拟合集并检查类间证据，而非继续以 test 挑种子。

### 3.4 回归与范围

局部分配 6 项、监督学习与诊断 18 项、原优化器筛选/响应/二进制模态 13 项回归通过，合计 37 项。覆盖可行重分配、单峰不能解释不同角色、分量预算、几何约束、常量输入处理、拟合集独占预处理统计、初始化基线和检查点恢复。Python 与 Notebook 静态编译通过。

没有执行整套 20 图留出、34 对象回查或所有 18 个扰动条件；这些保持在 Notebook 中供用户运行。小样本阳性结果不替代全体记忆保持、负例误接受与独立泛化评价。

## 4. 下一轮观察重点

1. 原图 34/34 是否保持，平移/亮度命中是否提高，布局负例是否仍被拒绝。
2. `reassigned` 是否转化为正确实体接受，或仅消除一个失败理由后仍被分数/覆盖拒绝。
3. 缩放已知几何下的失败是否集中在特定模态；不要直接整体下调分数门限。
4. 探针 `hold_correspondence` 与结构拒绝是否一致，变更区是否实际有可比较支持。
5. 分类头是否在多个固定种子下稳定优于初始化、固定类和简单 weak 规则。

受限分配增加了局部计算，尤其冲突多时有额外开销。本轮目标是修正检索行为，不承诺提速；性能问题可在正确性确认后根据实际调用统计处理。
